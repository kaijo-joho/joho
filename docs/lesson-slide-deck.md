# 座学ページ共通スライド基盤

`css/lesson-slide-deck.css`と`js/lesson-slide-deck.js`は、座学ページをHTML内のスライドとして表示する共通基盤である。2026年9月時点では`cp21.html`〜`cp22.html`、`dr31.html`〜`dr32.html`、`nw11.html`〜`nw13.html`などへ適用している。回路エディタは`tools/logic/index.html`へ独立し、スライド基盤を使用しない。共通基盤を変更するタスクは、この文書へ動作、設定、検証方法も記録する。

旧DR専用の`js/dr-slide-deck.js`は廃止し、この共通基盤へ統合している。DRページへ旧ファイルを再度読み込まない。

## シリーズの目次

座学シリーズの目次は英字2文字に`00`を付けたファイルとし、`dr00.html`、`cp00.html`、`nw00.html`を用意する。`py00.html`・`il00.html`と同じ`#html_index`を使い、`js/script_pages.js`が`pages.js`の`mainTitle`、`category`、`title`、`detail`、`fileName`からカテゴリ別のカードを生成する。教材名やリンクをHTMLへ重複記述しない。目次自体にはスライド基盤を適用しない。

目次の`#html_index`には`data-lesson-series="dr"`のようにシリーズ名を付ける。掲載する教材がない場合は「公開中の教材はありません。」と表示する。掲載条件は実習と同じく`release: true`かつ`show !== false`であり、公開前のページを独自に掲載しない。目次自身は`show: false`として自分自身のカードを作らない。

ページの登録・公開・教材との紐付けは[ページ一覧のデータフロー](page-list-data-flow.md)に従い、GSSを変更して生成する。目次を公開すると、同じ`mainTitle`を持つ座学ページの0枚目に目次へのリンクを表示する。目次のURLは登録された`fileName`から取得する。

## タイトルを表示する0枚目

`js/script.js`が`pages.js`から作る`#page_header`を、共通スライド基盤が0枚目として取り込む。HTMLへ表紙を追加・複製しない。0枚目にはシリーズ名`mainTitle`、ページタイトル`title`、説明`detail`、公開された`practiceFile`、公開済みのシリーズ目次へのリンク、「学習を始める」ボタンを表示する。

本文は従来どおり1〜N枚目とし、移動バーに「0 タイトル」を追加する。現在位置は`0 / N`〜`N / N`と表示し、分母は本文の枚数とする。既存の本文見出しIDと自動生成する本文スライドIDは変更しない。`#title`または`#page_header`で表紙へ直接移動できる。表紙を生成できなかった場合も本文スライドは従来の1枚目から表示する。

「学習を始める」は本文1枚目へ進み、その見出しにフォーカスを移す。説明や配付物が多い場合は0枚目の内部でスクロールする。390px幅でも説明を省略せず、文字サイズ・テーマの設定に従う。印刷時は表紙から本文まで順番に表示し、開始ボタンを隠す。JavaScript無効時の本文順は元のHTMLのままとする。

### ワークシートPDF

座学ページの`practiceFile`にはワークシートPDFの教材IDを登録する。共通レイアウトが展開済みの配列からファイル名と「PDFをダウンロード」リンクを生成し、URLは`pages.js`にある値をそのまま使う。複数のPDFにも対応する。配付WebアプリのURLをDrive URLへ独自に置換しない。サイト内の相対URLには`download`属性を付け、外部配付先は新しいタブで開く。

公開フラグが`false`の教材、URLがない教材、未登録の`practiceFile`にはリンクもダウンロード案内も表示しない。既存データとの互換性から、教材側の`release`省略は従来のファイル表示と同じく許容する。PDFの登録は`教材ファイル一覧`・`配布設定一覧`を正本として行い、同じIDが`ファイル一覧`へ反映されたことを確認してから`ページ一覧.practiceFile`で参照する。実習ページの配付ファイルの表示方法は変更しない。

2026年9月7日、目次3ページを`release: false`で登録・確認した後、ユーザーの承認を受けて既存座学9ページと合わせた12ページを`release: true`に変更した。目次にはDRの2ページ、LCの4ページ、NWの3ページを掲載し、新しい目次3ページも検索対象に含める。目次自身の`show: false`は維持する。9ページの`practiceFile`は未登録であり、実際のPDFリンクは教材IDを登録した後に表示される。

## 基本の呼び出し方

ページ固有のCSSより先に共通CSSを、教材固有のJavaScriptより後に共通JavaScriptを読み込む。

```html
<link rel="stylesheet" href="./css/lesson-slide-deck.css">
<link rel="stylesheet" href="./css/教材固有.css">

<script defer src="./js/main.js"></script>
<script defer src="./js/教材固有.js"></script>
<script defer src="./js/lesson-slide-deck.js"></script>
```

`body`へ`data-lesson-slide-deck`、各スライドに`data-lesson-slide`を付ける。スライド名は`data-lesson-slide-title`で指定する。

```html
<body data-lesson-slide-deck>
  <section data-lesson-slide data-lesson-slide-title="導入">
    <article>
      <h2 id="headline_1">(1) 導入</h2>
      <!-- 本文 -->
    </article>
  </section>

  <section data-lesson-slide data-lesson-slide-title="操作する">
    <article>
      <h2 id="headline_2">(2) 操作する</h2>
      <!-- 本文 -->
    </article>
  </section>
</body>
```

通常は0枚目のタイトルから表示する。エディタなどの専用UIを最初に開くページでは、`body`の`data-lesson-default-slide`へ対象スライド内の見出しIDを指定できる。URLに見出しハッシュがある場合は、ハッシュで指定されたスライドを優先する。

```html
<body data-lesson-slide-deck data-lesson-default-slide="headline_2">
```

## 上部のスライド移動バー

- 共通基盤が学校名ヘッダー`#site-header`の直後へ、前後ボタンとスライド選択メニューを1つだけ生成する。0枚目と本文のどちらを表示してもバーの位置を変えない。ヘッダーがない場合はスライド表示領域の直前へ置く。
- バーはヘッダーの直下に追従し、本文とは独立して表示する。ヘッダーの高さは初期表示、画面幅・文字サイズの変更時に再計測する。見た目だけCSSで順序を入れ替えず、DOM上もヘッダー、移動バー、スライド表示領域の順にする。
- 中央にはスライド順のボタンを横一列に並べ、番号とタイトルから直接選べるようにする。現在のスライドを背景・番号・下線で強調し、`aria-current="step"`でも示す。下部の移動バーは追加しない。
- 表示は、全タイトル、現在と次のタイトル、現在のタイトルだけ、ネイティブ`select`の順に切り替える。タイトルを省くボタンは番号だけを表示する。表示するタイトルは途中で切らず、番号だけの場合も`aria-label`と`title`には全文を残す。最終スライドでは存在しない「次」を優先対象に含めない。
- 切替は画面幅だけで決めず、中央に使える実際の幅、スライド枚数、タイトルの描画幅、文字サイズから判断する。全タイトルが収まらない場合は、まず左右の「前のスライド」「次のスライド」を矢印表示にして幅を確保し、それでも収まらなければタイトルを優先順に減らす。初期表示、フォント読込完了、画面幅・文字サイズ・現在スライドの変更時に再計測する。計測用のコピーは操作・読み上げの対象にしない。
- 560px以下、または全番号と現在のタイトルを一列に収められない場合は、中央をネイティブ`select`へ切り替える。「現在の番号 / 本文の枚数」とスライド名を表示し、開くと0枚目を含む全スライドから直接選べる。横並びボタンと`select`は同時に表示しない。前後ボタンの`aria-label`には移動先を含め、ボタンは幅・高さ44px以上、`select`は高さ44px以上を確保する。
- 前後ボタンや横並びのボタンで移動したらスライド見出しへフォーカスを移す。`select`で移動した場合は選択欄にフォーカスを残し、矢印キーによる連続選択を妨げない。短いタイトルを選び直して横並びが収まるようになっても、選択欄からフォーカスが外れるまでは`select`を保つ。画面幅・文字サイズを変更した場合は再判定する。Enter、Escapeなどはブラウザ標準の選択操作に任せる。`select`を開く操作では`joho:overlay-open`を送出し、教材名の目次や教材メニューなどを閉じる。
- 幅や文字サイズの変更で横並びボタンと`select`が切り替わるときは、非表示になる操作部品にフォーカスがあった場合だけ、新しい選択欄または現在の番号ボタンへフォーカスを引き継ぐ。本文の操作中にはフォーカスを移さない。
- URLハッシュやブラウザ履歴からスライドが変わった場合も、現在の番号ボタン、表示を優先するタイトル、`select`の選択値、読み上げ用の進行状況を同期する。
- 最終スライドでは、公開済みの次教材があるときに右ボタンを「次の教材」に切り替え、教材名を`aria-label`へ含める。遷移先は`js/pages.js`の`next`から公開対象だけを選び、次教材がなければ「完了」として無効化する。未掲載の教材へはクリック・キーボードともに遷移しない。
- LessonDockはヘッダーの書類アイコンへまとめ、検索アイコンとともに表示する。関連ページ一覧は教材名から開く。右下の固定ボタンと左端の目次ハンドルは設けない。実習・座学に共通の仕様は[ヘッダーの共通ナビゲーション](header-navigation.md)を参照する。
- スライド内の手順や問題の操作は対象の図・問題の近くに置く。「前の手順／次の手順」「次の問題」など対象が分かる名称を使い、共通のスライド移動と区別する。
- 印刷時は移動バーを隠し、画面上で`hidden`になっているスライドや表示切替パネルも元の順に表示する。印刷用セレクタは通常時の非表示指定を上書きできる詳細度にする。

## 通常表示のフッター

通常表示では、共通レイアウトが生成する`#site-footer`をスライドの直下へ表示する。著作権表記・文字色・書体・文字サイズは実習ページと共用し、座学の画面表示だけ上余白をなくして上下のpaddingを2px・8px、行の高さを1.4にする。標準サイズの1行表示では高さ約30pxとなる。本文と同じ幅にそろえ、左右8pxの内余白を設け、狭い画面では表記を自然に折り返す。他のページと同じ透明な背景のブロックとし、目立つ背景帯や角丸は付けない。

フッターは固定配置せず、通常の文書の流れに置く。共通スライド基盤は、画面の残り高さからフッターの実測高さとスライド下の8pxを引き、重なりを防ぐ。`ResizeObserver`でフッターの高さも監視し、折り返し・文字サイズ・フォント読込による変化へ追従する。従来どおり高さが非常に小さい画面ではスライドの最小高さ300pxを保ち、ページ全体を縦スクロールできる。

全画面時はフッターを非表示にして、その高さもスライドへ割り当てる。終了すると表記と通常の高さを戻す。印刷・JavaScript無効時・シリーズ目次・実習ページには、この座学専用の余白調整を適用しない。

変更時は、全座学ページの通常表示・全画面の開始と終了、デスクトップ・半画面・390px、全テーマ・文字サイズで、フッターの表示・折り返し・本文との重なり・下端の収まりを確認する。低い画面での縦スクロール、スライド内スクロール、印刷・JavaScript無効時の本文順も確認する。

2026年9月10日、ChromeとPlaywright WebKitで座学10ページの1440px・390pxにおける表示・全画面の開始と終了を確認した。`dr31`では1800px・915px・720px・390pxと全テーマ・文字サイズ、フッター自体の文字拡大による再計測、高さ400pxでの縦スクロールを確認した。1800px幅の全画面ではスライド幅1784pxを維持した。キーボード・タッチ・フォーカス復帰、スライド内スクロール・範囲入力、印刷・JavaScript無効時の本文順、実習`py21`と目次`dr00`の従来のフッター余白も確認し、構文・座学スライド・論理回路応用・音教材・公開リンクのテストに合格した。Safariアプリ自体は未確認である。

## スライドの全画面表示

`data-lesson-slide-deck`で共通基盤を初期化した座学ページでは、サイトヘッダーの文字サイズ・テーマ切替の右隣に「スライドを全画面表示」アイコンを生成する。実習ページやシリーズ目次には追加しない。各HTMLへのボタンの記述は不要である。

アイコンへのホバー、クリック・タップ、Enter・Spaceでは開始メニューだけを開く。メニュー内の「スライドを全画面表示」を明示的に押したときにブラウザのFullscreen APIを呼び出す。全画面中は学校名・関連ページ一覧・教材・検索・表示設定を含む`#site-header`を隠し、その分もスライドの表示領域へ割り当てる。常設する操作はスライドの前後移動・選択・全画面終了だけとする。上部のスライド移動バーは残し、同じ全画面ボタンをバーの右端へ移して「全画面表示を終了」に切り替える。終了ボタンまたはブラウザ標準のEsc操作で通常表示へ戻り、ボタンを元のヘッダーへ戻してフォーカスする。ブラウザ側の操作による終了も`fullscreenchange`で同期する。

全画面の対象要素は`document.documentElement`とする。ヘッダーを非表示にしつつ、本文外の補足dialogと文書の背景を維持するためである。ヘッダー内の機能は通常表示へ戻って利用する。スライドや教材固有のDOMは作り直さず、現在のスライド・URLハッシュ・穴埋めや入力の状態を維持する。全画面の切替時は`joho:overlay-open`で開いているパネルを閉じ、移動バーとスライドの高さ・幅を再計測する。全画面内で開いたdialogは既存の閉じる操作とフォーカス復帰に従う。

標準APIとSafariのWebKit接頭辞付きAPIに対応する。全画面APIが使えない環境ではアイコンを生成せず、通常の教材操作を提供する。要求が拒否された場合は切替前の表示を維持し、移動バー内に再試行の案内を表示する。状態の切替はAPIの成功に合わせ、疑似的な全画面表示へは切り替えない。アイコンの操作領域は44px、状態は`aria-pressed`、操作名は`aria-label`で示す。テーマ・文字サイズは既存の共通設定を引き継ぐ。

全画面時は移動バーとスライドの通常の最大幅1480pxを解除し、画面幅から左右各8pxを引いた幅まで広げる。高さは移動バーと下端余白を除いた画面の残りを使う。これにより、移動バーを含む教材領域がMacBookなど利用中の画面の縦横比に追従し、広い画面でも左右に大きな余白を残さない。画面の拡大・縮小に応じて本文を再配置し、図そのものの縦横比は保つ。通常表示へ戻ると96vw・最大1480pxの幅に戻す。

幅の上限解除はChrome・WebKitで1800×1125px・3588×2236pxを含む6種類のビューポートを検証した。1800px幅では座学9ページとも全画面の本文幅が1784pxになり、終了すると1480pxへ戻る。390px幅も含めて左右各8px、移動バーと本文の幅の一致、画面下端までの高さ、全テーマ・文字サイズ、全画面中のリサイズを確認した。今後の変更でも1480pxを超える画面幅でこの挙動を確認する。

検証時は全座学ページで開始メニュー・開始・終了、ヘッダーの表示復帰、スライド位置・ハッシュ・教材の入力状態を確認する。デスクトップ・半画面・390px幅で移動バーの選択UIと終了ボタンが収まり、本文内スクロールを使えることを確認する。キーボード・タッチ、ライト・ダーク・自動、3段階の文字サイズ、通常時の教材メニュー・検索、全画面時の補足dialog、要求拒否・非対応環境も確認する。ブラウザ自体のウィンドウ最大化とは区別し、実際のFullscreen APIによる動作と未確認の環境を記録する。

2026年9月8日、Chrome・WebKitで座学9ページの実際のFullscreen APIによる開始・終了を検証した。1440px・720px・390px幅、全テーマ・文字サイズ、教材の操作状態保持、検索・LessonDock・左目次・本文内外の補足dialog、キーボード・タッチ、印刷・JavaScript無効時を確認し、ページ内例外とローカル資産の404は発生しなかった。非対応・要求拒否・再試行はテスト用のAPI設定で確認し、接頭辞付きAPIの経路も検証した。Escによる終了はWebKitで確認済み。Chromeでは終了APIを直接呼び出した場合の状態・フォーカス復帰まで確認し、実画面のEsc操作とSafariアプリ自体での確認は未実施である。

## 専用UIを含むスライド

エディタや問題演習では、外側のスライドへレイアウト種別を指定する。

```html
<section data-lesson-slide data-lesson-slide-layout="workspace">
  <article>...</article>
</section>
```

指定できる値は`workspace`と`exercise`である。これらは本文余白を小さくし、操作領域を広く取る。矢印キーを教材内の操作に使う領域だけへ`data-lesson-slide-navigation-lock`を付ける。スライド全体には付けず、見出しへフォーカスがあるときは左右キーで前後移動できる状態を保つ。

大きな回路図、真理値表、エディタは文字やタップ対象を過度に縮小せず、その部品または現在のスライド内だけをスクロール可能にする。ページ全体の横スクロールは発生させない。

通常表示の本文幅は画面幅の96%まで広げ、1480pxを上限とする。狭い画面では左右8px以上の余白を残す。全画面時は前節のとおり幅の上限を解除し、画面に合わせる。

教材固有JavaScriptが表示内容の高さを大きく変えた場合は、`document`へ`joho:lesson-content-resize`を送出し、共通基盤へ表示領域の再計測を依頼する。

NWシリーズの語句の穴埋めは`js/network-lessons.js`の共通処理を使い、同じボタンの再操作で個別に非表示へ戻せる。表示数や連動する図を含む仕様は[Networkシリーズの編集方針](page-specific-editing-notes.md#networknwシリーズ)を参照する。

## 計算問題の式ビルダー

座学の計算問題では「問題の値を選ぶ → 式を組む → 自分で計算する → 判定を受ける」の順で学習する。問題文から値を読み取って式や答えを自動生成したり、式の入力途中に計算結果を表示したり、自動で約分・答えの補完をしたりしない。採点時に限り、入力された式を内部で評価する。

### 責務の分離

- `js/lesson-formula-core.js`はDOMに依存しない式の構造、演算、単位と式の同値性の検証を担う。量の役割の対応付けは教材側で宣言する。演算子を任意のJavaScriptとして評価しない。
- `js/lesson-formula-grader.js`はDOM非依存の共通採点を担い、数量の出自、換算方向、途中結果の参照、比較式と最終回答を判定する。音に依存せず、教材が宣言した単位・採点規則を使う。
- `js/lesson-formula-builder.js`は教材共通の式編集UI、カード挿入、選択した部品の削除・移動、参照操作を担う。編集履歴やundo/redoは持たない。
- 教材固有の`js/sound-formulas.js`などは問題データ、正解候補、教材用語と採点の対応を担う。既存の問題データや計算コアから正解条件を導き、日本語本文を解析して問題を作らない。
- `js/lesson-slide-deck.js`は引き続きスライド移動・表示を担い、式の計算や採点を持たない。式ビルダーを初期化できない場合も、スライド全体の操作を停止させない。

### 値と式の編集

- 問題から与えられた数値の量カードは、カード上では「数値・単位」と先頭のドラッグつまみだけを表示し、単位は数値より小さくする。余白と文字はコンパクトにするが、操作領域は44px以上を保つ。問題文の条件を同じ内容のバッジで繰り返さない。換算用の補助定数は数値だけとし、「kHz→Hz」のような換算方向のヒントは付けない。同じ数値・単位の候補を問題のカードと補助定数の間でも重複して並べない。自由入力も換算値は「単位なし」でよいが、問題から与えられた数量の単位・役割は維持する。自由入力欄は初期状態では枠とplaceholderだけとし、フォーカス時に通常の単位と「挿入」を横並びで表示する。狭い画面で数値欄とは折り返してよいが、単位選択と挿入ボタンは縦積みにしない。換算方向の選択は求めず、掛ける／割る向き・桁数は教材側の採点で確認する。
- 補助定数・その他の記号・操作ヘルプは本文の高さを変えないポップアップとし、ホバーに加えてクリック・タップ・Enterで開き、Escapeや外側の操作で閉じる。ポップアップ内へポインターやフォーカスを移しても閉じず、ドラッグ中も維持する。ArrowDownで候補へフォーカスを移せるようにし、Escapeで閉じた場合は入口へ戻す。スライド切替・全画面切替・他の共通オーバーレイ表示時は閉じる。問題の数値と重複を除いた補助定数の合計が8個以下の場合は、補助定数を初めから表示する。
- 式は数値・値カードと構造化された演算子 `+`、`−`、`×`、`÷`、`=`、括弧、分数、指数、比較記号 `<`、`≤`、`>`、`≥`から組み立てる。`+`、`−`、`×`、`÷`、`＝`は常時表示する。通常の`＝`はその行の手入力の答え欄を開く操作とし、式の途中で関係を表す等号は「その他の記号」の「等式の＝」から入れる。他の演算子・構造も同じ詳細から開く。カードや式の部品はドラッグで挿入・移動でき、クリック、タップ、キーボードでも同じ編集ができる。挿入slotは空欄時のplaceholder以外に文字を表示せず、`＋`ボタンは置かない。挿入位置のカーソルは明示的に位置を選んだ間だけ表示し、挿入・移動・削除後、欄外のクリックやフォーカス移動時には消す。
- 選択した式の部品は右上の小さい`×`（44pxの操作領域を確保）で削除できる。移動は部品を選択してから「選択を移動」を使う。各小問は独立した式を持ち、`＝`を押すまで答え欄は表示しない。式の末尾・`＝`・答え欄・「判定」を同じ横一列に配置し、長い式だけ枠内を横スクロールさせる。「途中式を追加」は同じ小問の既存式の下へ追加する。既存行の式と手入力の結果・行IDを保持し、新しい最終行で次の計算ができるようにする。複数行ある小問では最終行を削除して直前の行へ戻せるが、参照中の行は削除できない。
- ドラッグ中だけ挿入可能な場所を点線の枠で示し、二項演算子なら数値と数値の間など、構文上自然な位置を濃く、修正用のほかの位置を淡く示す。不自然な位置への挿入を禁止せず、正解の演算・単位・数値を推測するヒントにも使わない。選んだドロップ先はさらに強調して「ここへ挿入」と表示する。部品の左右や式の余白でも近くの挿入位置を選べるようにし、分数・指数の内側への挿入を優先する。1回のドロップで二重挿入しない。式や答え欄を切り替えたときは、前の行の挿入位置を使い続けない。
- 数値・参照・分数・括弧グループの右上の小さい指数入力先は、数値等をドラッグしている間だけ表示する。通常時・記号のドラッグ中は表示せず、ドロップ・取消後にも残さない。入力先の表示によって式の配置は動かさない。直接数値をドロップすると、その部品を底とする指数として追加し、元の値と単位・参照先は保持する。タップ・キーボードや複合的な式には「その他の記号」の指数テンプレートを使用する。入力操作で指数を計算したり単位を書き換えたりしない。
- 前の式の答え部分から後の式へドラッグして参照でき、同一問題の小問をまたぐ参照も可能とする。有効な数値を手入力すると、答えボックス内にドラッグ用つまみが現れる。これは正誤判定済みを意味せず、誤った途中結果も参照可能とする。つまみはクリック・タップ・Enterでも参照元として選べ、その後に後の式の挿入位置を選んで挿入する。Escapeで選択を取り消せる。別の参照元プルダウンや「この結果を使う」欄は設けない。参照カードは数値と小さい単位だけを表示し、前に矢印を付けない。参照元の値が変われば参照カード表示を更新するが、後続式へ手入力した数値は自動で書き換えない。
- 式の値、参照先、単位、演算子の意味を保った構造として扱う。未完成式、0除算、不正な参照、未対応単位があれば確定採点せず、修正箇所を案内する。
- スライド切替や全画面切替では編集中の状態を保ち、別の問題へ移るとその問題の入力を初期化する。再読み込み後に入力を復元せず、入力を外部へ送信しない。
- 式内の値・演算子間のgapと枠の上下余白は小さくする。マウス操作時の挿入slotは幅20px・高さ44pxを基本とし、coarse pointerでは44px幅を確保する。余白の削減で指数のドロップ先や削除ボタンが通常の挿入操作を奪わないことを検証する。長い式は引き続き式枠内だけを横スクロールする。

### 型を与える立式（最小ビット数）

中学段階では、必要最小ビット数の比較式を白紙から組み立てさせず、次の穴埋めを基本とする。

`2^□ ＜ □ ≦ 2^□　∴ □ bit　［判定］`

- 2つの底・不等号・`∴`は固定し、左の指数・問題の段階数または色数・右の指数・結論の4か所を入力する。17段階なら`2⁴ ＜ 17 ≦ 2⁵　∴ 5 bit`、16段階なら`2³ ＜ 16 ≦ 2⁴　∴ 4 bit`となる。
- `∴`には小さく「したがって」と添える。不等式と答えを等号でつながず、結論の入力欄と判定ボタンは初めから表示する。対数（log）は用いない。
- 指数はその位置の空欄に直接入力でき、中央の値はカードからドラッグ・タップでも入れられる。通常の式ビルダーの指数追加先を常設するのとは別機能とする。
- 右の指数は必要最小ビット数、左はその1つ前とする。比較式の3空欄と結論を別々に確認し、単に真となる広すぎる範囲や答えだけでは立式正解にしない。未入力・不正な値は採点を保留する。入力中に指数・結論を自動補完しない。
- 通常の四則演算は自由な式組み立てを維持する。型を与えるかどうかは問題定義で選び、教材ごとに別の編集UIを複製しない。

### 立式と答えの判定

- 立式と数値の答えは画面上でも集計上でも別々に扱う。同じ設問を再採点しても得点を二重加算しない。例題も判定できるが、スコア集計からは除外する。
- 行内の「判定」はその小問と必要な参照元を対象とし、独立した他の小問が未入力でも判定できる。途中式は結果と単位の確認だけを行い、スコアへ加算しない。判定後も式・答えを編集でき、再判定できる。正解の数値や模範解答は判定だけでは表示しない。
- 「解答を見る」を判定と別に用意する。開いたら解答・解説の全手順を一括表示し、「次へ」で解説を送らせない。解答を開閉しても入力は保持する。演習のスコアは同一問題の初回の確定判定のみを数え、修正後の再判定では表示を更新するが加算・上書きしない。次の問題で式・答え・解答の開閉状態を初期化する。
- 数値だけが偶然一致しても立式正解にしない。数量、単位、関係を検査し、許容する式の並べ替えや同値な分数表現は正解候補として明示する。音教材では換算用の`÷ 8`と`× (1/8)`などを単位なしでも同値に扱う。旧式の`÷ 8 bit/B`と`× (1/8) B/bit`も、量と単位の対応が正しければ利用できる。単位なしの定数を一般の数量と混同せず、1000／1024や換算方向の誤りは不正解とする。
- 生徒が手入力した値も、候補カードと同じ数値・単位・量の役割を持てば同じ値として扱う。正しい元の立式を保持して後続式へ参照できるようにする。例: `式1: 16 × 2 ÷ 8 = 4`を立て、次の式から式1の結果を参照する。計算済みの数値だけを入力したものは立式正解にしない。
- 判定は「式」「答え」を分けて示し、正しい式の計算ミス、単位の向きの誤り、誤答となった前式の参照を区別する。参照元を直したときも、後続式で生徒が入力した計算結果は自動更新しない。
- `17`段階を識別する問題では、`2^4 < 17 ≤ 2^5`のように必要なbit数の根拠となる不等式も式として確認する。
- 既存の1000/1024換算と許容誤差を維持する。丸め条件、換算規則、教材段階は問題データに従い、途中計算で新たに丸めない。

### 対象と検証

導入対象は`dr32`の本文2枚目の例題・3〜5枚目の演習、`dr31`の「数値の例」の計算4種、`dr41`の原稿由来の計算2問（4小問）、`dr42`の計算2問（3小問）、`dr43`の9枚目の印刷計算（横・縦の2小問）とする。`SoundCore`・`ImageCore`・`VideoCore`・`OutputCore`と各ページの問題定義から構成し、問題の条件・換算方式・丸めを維持する。`dr31`の確認例では説明を開く操作を別に設け、非スコアで何度でも判定できる。波形・画像の読み取り、符号化の表、説明のためにスライダーへ連動する計算は置き換えない。GASワークシートや他教材への自動展開は行わない。教材固有の条件は[ページ別編集メモ](page-specific-editing-notes.md)を参照する。

実装後はcore、教材adapter、ブラウザUIの新規テストに加え、既存の音教材・共通スライド・検索の検証を行う。ブラウザでは1440px・720px・390px、ライト・ダーク・自動、3段階の文字サイズ、全画面の開始・終了、ドラッグ、キーボード、タッチを確認する。選択部品の削除・移動、参照の更新と削除制限、同一問題・小問の参照範囲、式・答えの別集計、重複採点防止、未完成式などの採点保留も確認する。実施前の確認項目であり、合格済みの実績を意味しない。

### データと接続API

問題定義は`quantities`（与えられた数値）、`constants`（補助候補）、`units`（表示名と次元）、`sources`（数量の出自）、`tasks`（小問と回答単位）を持つ。音教材は`SoundFormulas.define(problem)`、画像・動画は`MediaFormulas.defineImage(kind)`・`defineVideo(kind)`、印刷計算は`OutputFormulas.definePrint()`で既存問題から導出する。採点APIは共通graderへ委ねる。自由入力の単位は`units`のうち問題・答えで使用するものと、問題定義の`manualUnits`から選ぶ。bit・B・KB・MBを自動換算せず別の単位として管理し、換算値を掛ける／割る方向も採点する。段階数・チャンネル数・桁数は物理的には無次元でも役割を区別し、単位なしの定数`2`をステレオの`2チャンネル`と同一視しない。単位なし換算の候補は`unitlessConversionChoices`で教材ごとに宣言できる。

`LessonFormulaBuilder.mount(host, definition, {onJudge, onChange})`は`getDraft()`、`setDraft(draft)`、`reset(definition)`、`setFeedback(judgment)`、`setDisabled(boolean)`、`destroy()`を返す。行内判定は`onJudge({rowId, taskId, intermediate, draft})`へ通知する。教材側が`SoundFormulas.grade(definition, draft, {taskId})`または`gradeRow(definition, draft, rowId)`を判定操作時だけ呼び、結果を`setFeedback`へ渡す。全小問一括の`grade(definition, draft)`も互換性のため残す。途中式・解答は次のような構造であり、計算済みの派生値を編集中の状態へ書き戻さない。

```js
{
  rows: [
    { id: 'r1', taskId: 'sample', tokens: [/* 構造化トークン */], result: '4', resultUnit: 'B', answerOpen: true },
    { id: 'r2', taskId: 'second', tokens: [{ kind: 'reference', rowId: 'r1' }], result: '', resultUnit: '', answerOpen: false }
  ],
  targets: { sample: 'r1', second: 'r2' }, // 小問ごとの採点対象の式
  answers: { sample: '4', second: '' }   // 生徒の手入力
}
```

値は`{kind:'value', value:'16', unit:'bit/sample'}`、演算子は`{kind:'operator', value:'×'}`、分数は`numerator`と`denominator`、指数は`base`と`exponent`、括弧は`body`に子トークン配列を持つ。各rowは必ず`taskId`を持ち、`targets`と`answers`は既存の互換形式を維持する。最終rowは中間結果の入力欄を持たず、その小問の`answers[taskId]`を、参照するときに限って当該rowの`result`・`resultUnit`として投影する。この投影は自動計算ではない。回答の単位は`task.answerUnit`を使い、比較式など最終回答を数値の式結果として扱わない小問は`answerIsResult: false`を問題定義へ明示する。数量の出自は教材側で数値・単位・役割から再照合し、クライアントのカードIDだけを信用しない。前式参照は手入力結果を数値計算に使い、元の式を立式判定へ引き継ぐ。参照元の式を補完したり結果を自動修正したりしない。

`row.answerOpen`は答え欄の表示状態だけを保持し、通常の`＝`を採点用トークンに混ぜない。旧draftに手入力済みの答え・結果がある場合も答え欄を復元する。最小ビット数の穴埋めは`rule:'minimum-bits'`、`scaffold:{type:'power-bounds',base:2}`、`answerIsResult:false`を宣言し、構造化トークンの指数・中央の値と`answers`へ手入力だけを保持する。結論欄は常に開き、区切りは`∴（したがって）`とする。色数の場合は`boundUnit`・`boundSymbol`で数量の役割を指定する。換算カードは`unit: ''`とし、換算の許容範囲は教材側の採点規則で決める。旧式との互換用の比の単位は残してよいが、自由入力の候補へ換算方向のヒントを再追加しない。

比較式や直接記入の結論を後の小問で使う場合だけ、教材が`conclusionQuantity:{unit, symbol}`を宣言する。画像の色数から求めたビット数は`bit/pixel`として画像サイズの式へ参照できる。比較式の場合は真偽値を数値へ変換せず、判定時に比較の根拠を検証して結論の由来を引き継ぐ。誤った手入力結果も表示・参照値はそのまま保持し、計算ミスとして分離する。根拠が未完成・不正なら参照先の採点は保留する。参照しない独立小問の判定は、他の空欄に妨げられない。

教材側で`taskPalettes: true`と各小問の`palette:{quantities,constants}`を指定すると、小問の中へ専用パレットを置く。`hideUnit`は選択カードの表示だけを省略し、採点用の単位を保持する。`rule/scaffold.type: given-value`は問題文から読む数値の直接記入用。`scaffold.prompt`に文を置き、`conclusionQuantity`で後の式へ参照する量を指定する。正解を入力欄へ補完せず、判定は答えのみを表示する。dr41問題2で使用し、他の最小ビット数問題の比較式は維持する。

初版は最大16行、各式250トークン、入れ子32段、整数指数の絶対値64までとし、多項式展開にも上限を設ける。過大な入力はブラウザを止めず採点保留にする。最小ビット数は与えられた段階数と隣接する2のべき乗の比較（または段階数が2のべき乗と等しい等式）で判定し、計算済みの境界値だけを置かない。前の式でべき乗を求め、その手入力結果を比較式で参照してもよい。

音教材の単位なし換算値は、判定時だけ許可された単位の候補を確認し、数量の由来・元の式・結果の単位が整合する場合に受理する。値だけから一律に単位を決めない。同じ`1000`でもkHzの換算とデータ量の換算を区別し、指数の`8`をbit/Bに置き換えない。候補は1式1024通りまでとし、上限超過は途中式へ分けるよう案内して判定を保留する。`1000²`、`1024²`やその分数表現も、採点用の候補だけを評価し、画面の式や手入力の答えを書き換えない。

## 1枚の中の表示切替

複数の説明を同時に縦積みしない場合は、表示切替グループを使う。

```html
<div data-lesson-view-group data-lesson-default-view="and">
  <div data-lesson-view-controls aria-label="ゲートを選ぶ">
    <button data-lesson-view="and">AND</button>
    <button data-lesson-view="or">OR</button>
  </div>
  <div id="gate-and" data-lesson-view-panel="and">...</div>
  <div id="gate-or" data-lesson-view-panel="or">...</div>
</div>
```

初期化後はタブとして動作し、左右キー・Home・Endで切り替えられる。パネル内のIDをURLハッシュへ指定すると、そのパネルを含むスライドと表示項目が直接開く。

## 補足情報

短い補足は`data-lesson-supplement-preview`でホバー・フォーカス時に示し、詳しい内容は`dialog`で開く。タッチ端末ではホバーを前提にせず、ボタンから同じ内容を開けるようにする。

```html
<button
  data-lesson-supplement-open="operation-guide"
  data-lesson-supplement-preview="詳しい操作を確認できます。"
>詳しい操作</button>

<dialog id="operation-guide" data-lesson-supplement-dialog>
  <button data-lesson-supplement-close aria-label="詳しい操作を閉じる">×</button>
  <!-- 補足本文 -->
</dialog>
```

ダイアログはEscape、閉じるボタン、背景の選択で閉じ、呼び出し元へフォーカスを戻す。

## 共通の動作

- 前後ボタン、現在位置、各スライドへの直接移動を自動生成する。
- 左右キーとPageUp／PageDownで前後移動する。フォーム、タブ、リンク、教材操作領域では奪わない。
- 現在の見出しIDをURLハッシュへ反映し、直リンクとブラウザ履歴から表示位置を復元する。
- 最終スライドの次ページは`js/pages.js`の`next`から取得し、HTMLへ重複記述しない。
- テーマ、3段階の文字サイズ、`prefers-reduced-motion`、印刷表示へ対応する。
- JavaScript無効時は元のHTML順で本文を表示する。

### ページ間リンクと掲載状態

`release: false`は、アップロード済みのHTMLをURLで直接確認できる状態のまま、他ページからのリンク掲載を止める設定とする。直接開いたページの表示や、同じページ内のスライド移動・ハッシュリンクは制限しない。

`js/script.js`の`window.isPageLinkReleased`で、リンク自身と遷移先の`pages.js`登録情報を確認する。どちらかが`release: false`ならリンクを作らない。IDを持たないURL指定も、登録された`fileName`と照合する。URLのクエリ・ハッシュや相対パスの表記差で未掲載判定を回避しない。登録のない補助ページや外部URLは従来どおり扱う。

この判定は上部の「次の教材」、本文末尾の次回案内、LessonDock、ヘッダーの戻り先、本文内の教材リンク、検索結果で共有する。`next`が明示されている場合は、その公開対象が空でも旧HTMLの`#next_page`へフォールバックしない。`data-lesson-slide-next-url`や旧HTMLからの取得でも同じ掲載判定を通す。

本文中のページ参照は`<span data-page-link="lc02">自由接続モード</span>`のようにページIDで指定する。共通レイアウトが公開済みページの`fileName`からリンクを作り、未掲載・未登録・JavaScript無効時は文言だけを表示する。登録済みの未掲載ページを指す既存の固定リンクも、共通レイアウト初期化時に文言へ置き換える。新しく固定URLを本文へ重複記述しない。
