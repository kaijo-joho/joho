# 「配付ファイル一覧」GSSとページ一覧の関係

この文書は、教材サイトのページ情報と配付物情報がどのシートで管理され、`js/pages.js`へどのように反映されるかを整理する。`js/pages.js`はGSSから作る生成物であり、直接編集しない。ページや講座に固有の編集判断は`docs/page-specific-editing-notes.md`へ記録する。

対象のGoogleスプレッドシート:

https://docs.google.com/spreadsheets/d/1d4--Rcap1BmZJPWJoEuK9teqoGn6Jyjzn_Q1FcDTvqE/edit

## 全体像

```text
教材ファイル一覧 ─┐
                  ├─> ファイル一覧（互換ビュー） ─┐
配布設定一覧 ─────┘                               │
                                                  │
DLファイル一覧 ───────────────────────────────────┤
impクイズ管理_cfg ────────────────────────────────┤
ページ一覧 ───────────────────────────────────────┴─> js/pages.js ─> 教材サイト
```

`pages.js`生成処理が直接読むのは、`ページ一覧`、`ファイル一覧`、`DLファイル一覧`、`impクイズ管理_cfg`の4シートである。`ファイル一覧`は、正本である`教材ファイル一覧`と`配布設定一覧`を同じ`id`で結合した既存GAS向け互換ビューである。

## `ページ一覧`への登録範囲

`ページ一覧`はリポジトリ内にあるHTMLファイルすべての一覧ではない。次のようなHTMLは、用途に応じて`ページ一覧`へ登録しなくてよい。

- 生徒へ配付するHTMLファイル
- サンプル、例題、解答ファイル
- 他のページから限定的に利用する補助ページ
- 共通ナビゲーションや前後関係で管理する必要がないページ

新しいHTMLを共通ナビゲーション、前後関係、教材リンクなどと連動するページとして管理する場合は、`ページ一覧`へ登録する。新規行の`release`は必ず`FALSE`とし、`js/pages.js`を再生成して非掲載状態で確認する。公開するときは、確認後に`release`を`TRUE`へ変更して再生成する。

`release: false`はアクセス制御ではない。HTMLファイルをGitHub Pagesへpushした時点で、ナビゲーションや検索に掲載されていなくても、URLを直接指定すれば閲覧できる可能性がある。本当に非公開とすべき試験、解答、個人情報などはリポジトリへpushしない。

## 各シートの責務

| シート | 位置付け | 主キー | 主な責務 | `ページ一覧`との関係 |
| --- | --- | --- | --- | --- |
| `ページ一覧` | ページの正本 | `id` | HTMLファイル名、題名、カテゴリ、公開状態、表示順、前後関係、利用する教材ID | 起点 |
| `教材ファイル一覧` | 教材ファイルの正本 | `id` | 原本・解答・問題ファイル、Drive ID、MIME、生成方法、生成状態 | `ファイル一覧`を介して間接的に参照 |
| `配布設定一覧` | 公開・配付設定の正本 | `id` | 教材の公開、解答公開、対象学年、提出先、戻り先、配付URL | `ファイル一覧`を介して間接的に参照 |
| `ファイル一覧` | 互換ビュー | `id` | 上記2シートを旧GASが読める形へ投影 | `practiceFile`、`exampleFile`、`questionFile`の直接の参照先 |
| `元ファイル一覧` | 互換ビュー | `id` | 原本・解答側の旧GAS互換情報 | `pages.js`生成では直接参照しない |
| `DLファイル一覧` | サイト配付ファイル台帳 | `id` | リポジトリ内のHTML・素材などのパスと提出先 | `dlFile`の直接の参照先 |
| `impクイズ管理_cfg` | クイズ取込データ | `quizId` | クイズ名、公開状態、対象学年、実行URL | `quizForm`の直接の参照先 |

`フォーム一覧`はフォーム自体の管理台帳であり、`quizForm`の直接の参照先ではない。`課題設定`も授業・課題運用に使う別の台帳であり、`pages.js`生成の直接入力ではない。

## `ページ一覧`の参照欄

| 列 | 値の意味 | 参照先 |
| --- | --- | --- |
| `practiceFile` | 配付ノートブックや実習ファイルのID | `ファイル一覧.id` |
| `exampleFile` | 例題ファイルのID | `ファイル一覧.id` |
| `questionFile` | 演習問題のID | `ファイル一覧.id` |
| `dlFile` | サイト内から直接配付するファイルのID | `DLファイル一覧.id` |
| `quizForm` | 確認テストのID | `impクイズ管理_cfg.quizId` |
| `back` | 戻り先ページのID。1件を指定する | `ページ一覧.id` |
| `next` | 次ページのID。複数指定できる | `ページ一覧.id` |

- 参照欄にはURLではなくIDを入力する。
- 複数のIDは半角カンマで区切る。現行生成処理は分割時に空白を除去しないため、カンマの後を含めてIDの前後へ空白を入れない。
- 真偽値の`FALSE`または空欄は「参照なし」を表し、文字列のIDとして扱わない。
- `ファイル一覧`の空IDや区切り用ID`---`は参照しない。

## 公開判定の層

公開に関係する値は役割が異なる。

- `ページ一覧.release`: ページ自体を公開対象にするか。
- `ページ一覧.show`: 公開済みページを目次などへ表示するか。ページ公開そのものとは別。
- `配布設定一覧.release`: 配付物リンクを公開するか。互換ビューの`ファイル一覧.release`を経由して`pages.js`へ入る。
- `impクイズ管理_cfg.release`: クイズリンクを公開するか。
- `教材ファイル一覧.managed`: 自動生成処理の対象か。公開状態ではない。
- `教材ファイル一覧.generationStatus`: 生成処理の状態。公開状態ではない。

したがって、`managed: false`だけを理由に`ページ一覧`から教材IDを外さない。ページと教材の公開可否は、それぞれの`release`と授業上の意図で判断する。

## `pages.js`生成時の変換

`ページ一覧`にあるIDは、GASの生成処理によってサイトが利用できるオブジェクトへ展開される。

- `practiceFile`、`exampleFile`、`questionFile`は、`ファイル一覧`から題名と公開状態を取得し、配付Webアプリの`target=<id>`リンクへ変換する。
- `dlFile`は、`DLファイル一覧`のリポジトリ内パスと提出URLを持つリンクへ変換する。
- `quizForm`は、`impクイズ管理_cfg`の題名、公開状態、実行URLを持つリンクへ変換する。
- `next`は、遷移先ページの題名、説明、HTMLファイル名を持つリンクへ変換する。
- `back`からは、戻り先の`fileName`を使って`backFile`が生成される。

ブラウザ側の`js/script_pages.js`は展開済みの`window.pages`を利用する。各HTMLで同じURL生成や台帳結合を再実装しない。

## 更新手順

1. 変更内容の正本を特定する。
   - ページ名、公開、順序、前後関係、教材との関連付け: `ページ一覧`
   - ファイル実体、原本・問題・解答、生成方法: `教材ファイル一覧`
   - 教材公開、学年、提出先、戻り先: `配布設定一覧`
   - リポジトリ内配付ファイル: `DLファイル一覧`
   - 確認テスト: クイズ側の正本と`impクイズ管理_cfg`
2. `id`または`quizId`の重複と参照切れがないことを確認する。
3. 教材の正本を変更した場合は、同じ`id`の値が`ファイル一覧`へ正しく反映されたことを確認する。互換ビューへ直接同じ変更を書かない。
4. GAS側の`run_previewPagesJsGeneration()`で、生成エラー、警告、既存版との差分を確認する。
5. `ページ一覧`を変更した場合は、`exportData_to_pages_js()`で`js/pages.js`を再生成する。生成結果を再現するために`js/pages.js`を直接編集しない。
6. リポジトリ内の`js/pages.js`が変わった場合は、検索索引を再生成して検証する。

`ページ一覧`で管理するページの追加では、HTMLファイルの追加、`release: false`での行追加、`js/pages.js`の再生成を一連の作業として扱う。`ページ一覧`へ登録しないHTMLファイルの追加では、そのためだけに`ページ一覧`や`js/pages.js`を変更しない。

## 避けること

- `ページ一覧`の参照欄へDrive URLやWebアプリURLを直接入力する。
- 正本と互換ビューの両方を手作業で同じ内容へ更新する。
- `ファイル一覧`や`元ファイル一覧`を正本として新しい運用を追加する。
- `quizForm`を`フォーム一覧`のIDへ結び付ける。
- `js/pages.js`を直接編集する。
- `ページ一覧`で管理する新規ページをHTMLだけに追加し、`release: false`での登録と`js/pages.js`の再生成を省略する。
- 全体生成に依頼外の差分が含まれる状態で、そのまま公開する。
