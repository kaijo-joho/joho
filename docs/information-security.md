## 内容・図の条件

- CIAは守りたい状態。一つの対策を一つの性質へ固定しない。完全性は正規更新を否定せず、可用性は許可された利用者を前提にする。
- 盗聴は正当な通信から第三者へ分岐する図。フィッシングは、偽の案内で本人に入力させる手口として区別する。確認先は案内内のリンク・番号ではなく、既知の正規経路とする。
- ID、認証、認可を区別し、認証後も閲覧可・編集不可など権限差があることを示す。所持要素は登録済み機器等を制御していることを確認する。
- 多要素認証は異なる種類の要素を二つ以上用いる。効果と残るフィッシングのリスクを同じ可視画面に置き、絶対的な安全を保証しない。
- マルウェアの呼称は広がり方・偽装・働きなどの観点が重なり得る。単純な排他的分類や危険度の採点をしない。
- バックアップは事故前に保存し、事故後に保存時点へ復元する。冗長化は停止を減らすため予備へ切り替えることで、過去の正しい状態へ戻すことと区別する。
- 更新は既知の弱点への対処、ファイアウォールはルールによる通信制御、ログは発見・調査、電子署名は検証・改ざん検出として効果を説明する。

安全対策の出典はIPA、定義・認証の補足はNISTの一次資料を2026-10-03に確認し、本文近くへリンクする。罪名・刑罰・法改正の監修へ広げない。実パスワード入力、攻撃の実行、外部送信、状態保存、成績判定は実装しない。

## 実装・検証

スライド操作は既存lesson-slide-deck、条件切替は既存information-society.jsを共用する。既存ISファイルを変更せず、新しいinformation-security.cssを.is-securityへ限定する。information-security.jsは語句の初期折畳みと印刷時の展開・復元だけを扱う。

全比較状態・語句・補足はHTMLソースで可視にする。JavaScript無効時は機能しない操作を隠し、全文を読める。図はtitle・descを付けた独自inline SVGとし、必要な条件・意味をHTMLにも置く。印刷では全状態と語句・補足を展開する。

印刷PDFの実確認で、大きな比較枠が次ページへ送られ広い空白ができたため、IS4xの印刷時だけモデルの途中改ページを許し、グリッドを文書順の1列にする。語句の説明・図は途中で分割せず、画面がダーク設定でも白い用紙で読める色にする。画面専用のスキップリンク・フォーカス枠は印刷しない。
