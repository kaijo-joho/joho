- 各単元は、原則として「基本 → 自由操作・実験 → 問題演習」の流れで構成する。
- 座学・概念説明をウェブ化するページは、縦に全章を並べるのではなく、次へ進むスライド形式を基本とする。問題演習は内容に適したUIを優先し、無理にスライド形式へ統一しない。
- `dr31.html`と`dr32.html`は手書きHTMLに`js/dr-slide-deck.js`を適用したページであり、Googleスライド由来教材の生成対象ではない。`config/slide-pages.json`に登録されていない限り、通常のHTMLとして直接編集する。

### スライド形式の共通仕様

- 対象ページの`body`に`data-dr-slide-deck`、各スライドに`data-dr-slide`と`data-dr-slide-title`を設定する。
- 前後ボタンとページ内の進行状況をスライド下部へ置く。最後のスライドから次教材へ進める場合は、`data-dr-slide-next-url`と`data-dr-slide-next-label`を使う。
- 見出しIDを含むURLのハッシュから、該当スライドを直接開ける状態を保つ。
- 全画面・最大化時におおむね1画面へ収めつつ、MacBook Airの画面を左右半分にした幅や390px幅でも操作できるようにする。内容が収まらない場合は、ページ全体ではなく表示中のスライド内をスクロールさせ、横長SVGには必要に応じて横スクロールを用意する。
- JavaScriptが動かない場合も本文を上から読める構造を保ち、次教材への通常リンクをHTMLに残す。スライド初期化後だけ、重複する次ページ案内やフッターを隠す。
- スライド移動で見出しへフォーカスできること、左右キー・Page Up・Page Downで移動できること、フォーム操作中にはキー移動を奪わないことを維持する。

### 音のデジタル表現（`dr31`〜`dr33`）

- 教材内容・説明順・用語は、ユーザー作成の「音のデジタル表現」授業スライドとPDFを基準にする。以前参照した教科書付録は基準資料にしない。原本へアクセスできない場合は、確認済みとして扱わない。
- 学習者向け本文はウェブページだけで完結させ、「授業資料を参照」「資料の例」のように外部資料の閲覧を前提とする表現を入れない。
- 原本にない専門用語を学習者向け表示へ追加しない。特に「エイリアシング」「ナイキスト周波数」は使わず、「元の波形とは異なる波形として見える」「同じ標本値から区別できない別の波形」など、ページ内で意味が分かる表現にする。内部の関数名まで変更する必要はない。
- PCMは「パルス符号変調」の略として扱い、原本にない定義や仕組みを独自に付け足さない。
- `dr31`は、最初にアナログ波形を示し、アナログとデジタル、標本化・量子化・符号化を順に説明してから、標本化周波数や量子化ビット数を変更する自由操作へ進む。
- `dr31`の標本化・量子化・符号化は別スライドへ分割せず、同じSVGへ要素を累積表示する1スライドの教材とする。最初はアナログ波形だけを表示し、標本化では時間方向の区切り、量子化では段階と値、符号化では2進数を順に加える。
- `dr31`の工程見出しは「0. アナログ波形」「1. 標本化」「2. 量子化」「3. 符号化」で統一する。内部状態を1〜4で保持していても、学習者向け番号へそのまま露出させない。
- `dr31`の可変グラフでは位相を操作項目にしない。周波数の異なる2つの正弦波へ同じ位相角を加えると合成波の形が変わるため、波形全体の平行移動と混同しやすい。位相は各成分を別々に確認できる`dr32`で扱い、将来`dr31`で平行移動を扱う場合は位相角ではなく時間移動として設計する。
- `dr31`の可変グラフでは、0. アナログ波形の段階で標本化周波数と量子化ビット数を無効にし、1. 標本化では量子化ビット数だけを無効にする。標本化周期は標本化周波数の操作欄、量子化段階数は量子化ビット数の操作欄へまとめ、独立した計算カードを重複表示しない。
- `dr31`の条件変更スライドではグラフの時間範囲を0〜1.2秒とし、操作欄には標本化周期と量子化段階数だけを表示する。標本数、量子化の幅、グラフ下の標本値表は、グラフと重複するため表示しない。選択した標本の値はグラフ直下の短い表示で確認できる状態を保つ。
- 工程の追加は理解を助ける短いフェード・ワイプで示し、`prefers-reduced-motion`ではアニメーションを停止する。補足は`i`、`?`、`!`のアイコンからホバー・フォーカス・タップで確認できるようにしてよいが、学習に必須の情報をアイコン内だけへ隠さない。
- 標本のホバー・フォーカス同期は対応する線と点を太くする程度に留め、標本区間全体を背景色で囲まない。ポインタまたはキーボードフォーカスがグラフ外へ出たときは強調を解除する。
- `dr32`の標本化定理は、標本化周波数が成分波の最大周波数の「2倍より大きい」「2倍ちょうど」「2倍より小さい」を区別する。2倍ちょうどは位相によって元の波形を一意に判断できない場合がある境界として示す。
- `dr32`の破線は「同じ標本点を通り得る別の波形」であり、復元された正解波形とは説明しない。標本点を折れ線で結んだものを復元波形として表示しない。
- `dr33`は3カテゴリのタブ型問題演習を維持する。同じ問題を複数回判定しても解答数・正解数を重複加算せず、標本単位の正誤と考え方を示す。
- 音声データ量の問題では、1000倍換算と1024倍換算を暗黙に切り替えず、各問題文へ換算規則を明記する。

### 計算と問題生成の規則

- `SoundCore`はDOMに依存させず、標本化、量子化、符号化、データ量、標本化定理の判定などの正解計算を担う。Controllerには入力状態だけを持たせ、派生値を重複保存しない。
- 基本の量子化範囲は0以上8未満とし、表現値を`最小値 + 段階値 × 量子化幅`で求める。最も近い表現値へ丸め、ちょうど中間なら上側を選び、範囲外は最小または最大の段階値へクリッピングする。
- 通常のランダム問題では量子化境界ちょうどの値を避ける。波形読み取り問題は正解となる格子上の標本値を先に決め、その点を通る滑らかな波形を描く。
- 問題の正解値は可能な限り`SoundCore`から生成し、宣言データへ同じ正解を重複して手入力しない。乱数は再現可能なシードを使い、同じ問題が連続しにくい状態を保つ。
