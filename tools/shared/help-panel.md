# 操作しながら読める共通ヘルプ

2026-09-15実装。論理回路エディタ0.4 BETAで使用しています。他アプリは各担当が組み込みます。共通化したのは小窓の表示・操作・設定保存で、アプリ固有の説明や編集処理は共通部品へ含めません。

## 画面と操作の契約

- `?`から開く**非モーダルの小窓**です。背景を暗くしたり、編集画面を操作不能にしたりしません。外側をクリックしても閉じません。右の真理値表・テンプレート・書き出しパネルとは独立し、同時に利用できます。
- 見出し、項目の選択欄、本文、下部の「位置を戻す」「編集へ戻る」で構成します。本文だけを縦スクロールし、項目選択や閉じる操作は残します。
- 本文は「つなぐ」「保存する」など目的別に分け、最初に2〜3手順、補足は`details`へまとめます。操作対象を変えても、読んでいる項目を自動で切り替えません。
- 最後に「このアプリについて」を置き、推奨環境、ご利用にあたって、保存先・外部送信の有無、教育用モデルの限界、バージョン、学校名、Copyrightを明示します。本文・法的表記はアプリ側の責任です。課題モードの通信説明を通常モードから無条件に流用しません。
- 「−」で見出しと現在の項目だけに最小化し、復元ボタンまたは`?`で元に戻します。展開中に`?`を押すと閉じます。閉じても位置・大きさ・項目・読んでいた位置は保持します。
- 保存確認、全消去確認などは従来どおり**モーダル**です。確認中はヘルプを含む背面の操作を止め、確認を閉じるとヘルプはそのまま利用できます。

### 大きさと配置

| 画面 | 挙動 |
|---|---|
| 851px以上 | 初期400×440 CSS px、作図領域の右下付近。見出しをドラッグして移動。右端・下端・右下の角でサイズ変更。幅320〜700px、高さは原則280px以上 |
| 850px以下 | 利用可能領域の下部に横幅いっぱいで表示。見出しの上下ドラッグで高さ変更。既定は利用可能高さの45%、高さ360px以上ある場合は60%が上限 |
| 高さが足りない画面 | 最小サイズを画面内へ縮める。表示範囲は`visualViewport`とアプリが渡す領域の共通部分へ制限 |

単位はCSS pxです。標準位置はアプリのツールバーや下部ステータスを避ける`bounds()`・`initialRight()`で調整します。画面端に8pxの余白を設け、指定領域が極端に狭い場合はビューポートを使います。小窓が邪魔なときは移動・縮小・最小化します。狭い画面でも画面全体を覆うモーダルへは切り替えません。

広い画面の位置と、狭い画面の高さは別に保存します。画面幅を戻すと元のデスクトップ配置を使います。「位置を戻す」は配置だけを標準化し、項目・作品・ズーム・右パネルを変更しません。

### フォーカスとキー操作

| 操作 | 結果 |
|---|---|
| 開く | 項目選択へフォーカス。`aria-expanded=true` |
| Tab / Shift+Tab | 小窓内外を通常の順で移動。フォーカスを閉じ込めない |
| 見出し上の矢印キー | 16px移動。Shift併用で64px。狭い画面の上下キーは高さ変更 |
| サイズ変更ハンドル上の矢印キー | 横・縦のサイズ変更。Shift併用で64px |
| 見出し・ハンドル上のEnter / Home | 標準の位置とサイズへ戻す |
| ヘルプをドラッグ中のEscape | 移動・サイズ変更だけを取り消す |
| 開いた補足内のEscape | その`details`を閉じ、`summary`へフォーカス |
| その他のヘルプ内のEscape / 閉じる | 小窓を閉じ、開いたボタンへフォーカスを戻す |
| 「編集へ戻る」 | 小窓を残して、アプリが指定した編集領域へフォーカス |
| 編集画面でのEscape | 通常の作図操作の取消・選択解除。ヘルプは閉じない |

アイコンボタン、項目選択、補足、右下のサイズ変更は44px以上の操作範囲を持ちます。右・下の細い境界は補助的なドラッグ領域です。ドラッグだけを唯一の手段にせず、キー操作と標準位置へ戻す操作を併設します。`aria-label`・`:focus-visible`を設け、ツールチップ用の`data-tip`を提供します。ツールチップの表示処理は各アプリの既存処理を使います。

## 組み込み方

`help-panel.css`と`help-panel.js`を1回ずつ読み込み、アプリの初期化から`JohoToolHelp.create()`を呼びます。ESモジュールや回路エンジンは不要です。自動初期化・外部通信は行いません。

```html
<link rel="stylesheet" href="../shared/help-panel.css">
<script defer src="../shared/help-panel.js"></script>
<script defer src="editor.js"></script>

<button id="help-button" type="button" aria-label="操作方法">?</button>
<!-- キャンバスのキーボードイベント領域の外、bodyの直下に置く -->
<aside id="operation-help" hidden>
  <section data-help-topic="parts" data-help-title="部品を置く">
    <h3>部品を置く</h3>
    <ol><li>追加したい部品を選びます。</li><li>作図領域へ置きます。</li></ol>
    <details><summary>位置を調整する</summary><p>アプリ固有の操作を記載します。</p></details>
  </section>
  <section data-help-topic="about" data-help-title="このアプリについて">
    <h3>このアプリについて</h3>
    <p>推奨環境・ご利用にあたって・バージョン・学校名・Copyright。</p>
  </section>
</aside>
```

`root`の直下にある`[data-help-topic]`が項目です。IDは小文字英字で始まり、小文字英数字・ハイフンだけを使用し、重複させません。保存済み設定と結び付くため、説明の文言修正だけでIDを変えないでください。選択欄の表示名は`data-help-title`、なければ`h3`の文字です。本文は信頼できるアプリ内HTMLで用意し、ユーザー入力や読み込みファイルをHTMLとして挿入しません。

```js
let help;
const isEditing = () => Boolean(editor.drag || editor.connecting || editor.resizing);
try {
  help = JohoToolHelp.create({
    root: document.querySelector('#operation-help'),
    opener: document.querySelector('#help-button'),
    title: 'アプリの使い方',
    storageKey: 'joho.example.help.v1', // アプリごとに別のキー
    bounds: () => ({
      top: document.querySelector('.top').getBoundingClientRect().bottom + 8,
      bottom: document.querySelector('#stage').getBoundingClientRect().bottom - 8
    }),
    initialRight: () => document.querySelector('#stage').getBoundingClientRect().right - 12,
    isBusy: isEditing,
    returnToEditor: () => editor.focus()
  });
} catch (error) {
  // ヘルプだけが読めなくても、作品の編集・保存は続けられるようにする。
  document.querySelector('#operation-help').hidden = true;
  document.querySelector('#help-button').disabled = true;
}
```

この例の`editor`・`.top`・`#stage`は各アプリに置き換えます。`bounds`の省略時はビューポート、`initialRight`の省略時は許容範囲の右端を使います。`title`の省略時は「使い方」、`returnToEditor`の省略時は開くボタンへ戻ります。`isBusy`の省略時は常にfalseです。

| API | 契約 |
|---|---|
| `create(options)` | 小窓を組み立てる。初期状態は非表示。同じrootには同じインスタンスを返す |
| `help.open(topicId?)` | 開く／最小化から復帰する。有効なIDならその項目へ。編集ドラッグ中・`dialog[open]`がある間は何もしない |
| `help.close(restoreFocus = true)` | 閉じる。全画面終了や画面の破棄ではfalseを指定できる |
| `help.selectTopic(topicId)` | 項目を選ぶ。不明なIDは無視。小窓を勝手に開かない |
| `help.refresh()` | 作図領域変更後に配置を再制限。進行中の小窓ドラッグは取り消す |
| `help.interacting` | 小窓を移動／サイズ変更中ならtrue。アプリの操作中判定へ加える |
| `help.root` | 非モーダル小窓のDOM要素。イベントの対象範囲判定に使う |
| `help.destroy()` | 閉じてイベント・監視を除去し、元の本文sectionをroot直下へ戻す。再初期化可 |

### アプリ側で必ず合わせる箇所

1. **ショートカット:** ヘルプにフォーカスがある間、Delete・Undo・保存などの編集用ショートカットを発動させない。一方、ヘルプを開いているという理由だけで編集画面の操作を止めない。`document`のハンドラーでは`if (help?.root.contains(event.target)) return;`を既存の入力欄・変換中・操作中判定へ加えます。キャプチャ段階で編集キーを処理するアプリも、そのハンドラーで除外します。
2. **開く操作:** `create()`が開くボタンのクリックを登録します。旧ヘルプの`showModal()`・クリックハンドラー・`data-lesson-supplement-open`等は外し、二重に開かないようにします。`?`キーの処理はアプリがこのボタンをクリックするか`open()`へ接続します。
3. **モーダル:** rootは`aside role="dialog" aria-modal="false"`です。`<dialog>`にしません。保存等の本当の確認は`showModal()`のままとし、ネイティブの背面操作防止を使います。独自モーダルの場合はアプリ側でヘルプも操作不可にし、完了時に戻します。
4. **右パネルと排他制御:** ヘルプを排他的なメニュー／モーダルの一覧に含めない。狭い画面の右パネルを外側クリックで閉じる処理でも、`.tool-help`内の操作は除外します。ヘルプの外側クリックでヘルプを閉じる処理は追加しません。
5. **動的な領域変更:** ウィンドウと`visualViewport`の変化は共通部品が監視します。アプリ内部で配置可能領域を大きく変えたら`refresh()`を呼びます。全画面はヘルプも含む要素を対象にし、全画面終了時は`close(false)`等で既存のフォーカス復帰に従います。
6. **テーマと倍率:** アプリの`--panel`・`--text`・`--line`・`--accent`、任意の`--muted`・`--hover`・`--shadow`・`--accent-soft`と文字サイズを継承します。body直下でもテーマ変数が届くように定義します。共通CSSは`.tool-help`内に限定し、他のアプリのdialogやh3へ広げません。z-indexは30。アプリのメニュー・ツールチップとの重なり順も確認します。
7. **保存との分離:** ヘルプを読んだだけで文書の変更、Undoの追加、下書き更新、保存済み判定の変更を起こさない。ヘルプの読込み失敗や設定保存拒否でも、編集・既存保存を壊さないよう初期化を分離します。

単一HTML構成のアプリを、この部品だけのために全面分割しません。共通ファイルを参照する方式を基本とし、単体配布が必要なら依存ファイルを含める配布方式を担当者と決めます。仕様本文や共通JSをアプリ別に手作業で複製しません。

## 設定保存と限界

```js
// storageKeyで指定したlocalStorage。作品・履歴・氏名などは入れない。
{
  version: 1,
  geometry: { x: 500, y: 300, width: 400, height: 440 },
  compactHeight: 320,
  topic: 'parts',
  scrolls: { parts: 0, about: 180 }
}
```

- 読込み時は版・文字数（8192文字以下）・数値・項目IDを確認し、壊れた値は既定値へ戻します。位置は実際の画面へ再制限します。`storageKey`を省略すると永続化しません。
- 初期化しただけでは書き込みません。開閉・配置・項目変更、スクロール後の短い待ち時間、ページを離れる際に設定を保存します。記録するのは表示設定だけで、操作の逐次履歴ではありません。別タブとの同期やクラウド送信はしません。
- ページ再読込み時は**閉じた状態**で開始します。最小化状態は永続化しません。開くと最後の項目・配置・本文スクロール位置を使います。
- 補足の開閉は同じページ内で保持しますが、再読込み後はHTMLの既定状態に戻ります。本文変更・文字サイズ変更・補足の開閉で高さが変わった場合、保存したスクロール位置は表示可能な範囲へ制限されます。
- 保存領域の読書き拒否でもヘルプは操作できます。位置等は再読込み後に引き継げない場合があります。作品・下書きのキーを削除したり上書きしたりしません。
- 現時点ではヘルプ内検索、ボタン位置の強調、操作に追従する自動項目選択、別ウィンドウへの分離はありません。必要になったら共通部品のAPIとして検討します。

## 検証

リポジトリをローカルHTTPサーバーで配信し、PlaywrightとGoogle Chromeが利用できるNode環境で実行します。既定URLは`http://127.0.0.1:8765/`、変更時は`JOHO_TEST_URL`を指定します。

```sh
node --check tools/shared/help-panel.js
node --check tools/logic/editor.js
node scripts/test-tool-help-browser.mjs
node scripts/test-logic-tool-browser.mjs
node scripts/test-logic-tool-usability-browser.mjs
```

単独の別アプリ相当の画面と、論理回路エディタで確認します。Google Chrome／Playwright WebKit、1440・760・390px、ライト・ダーク・自動、文字3段階、ドラッグ・キーボード・タップ、位置と読書位置の復元、非モーダル編集中の部品追加・配線、保存確認との共存、設定破損・保存拒否・ヘルプJS取得失敗を対象とします。移動は実マウスイベントを使い、pointer captureを差し替えません。

実際のSafariアプリでの手操作、タッチ端末の指による操作、他のエディタへの実組込みは別途確認が必要です。他アプリへ適用するときは、共有ファイルのテストだけで完了とせず、そのアプリ固有の編集・保存・全画面・キー操作の回帰検査も行います。
