# 教員・指定デモ用アカウントでの問題配布・実機検証

2026-10-16。対象は学校の教員アカウント2名（所有教員と追加教員）と、明示指定した高1デモ用アカウント1名による問題一覧・問題文・雛形の取得。当初の新規GAS・OAuth・専用接続に加え、指定追加教員1名の配布利用が承認済み。配置・接続の実施状況と学校実機での確認結果は別に記録し、コードや合成テストの完了だけで実機検証済みとは扱わない。

## 配布の流れ

所有教員が検証用GASで手動配信する。「配付ファイル一覧」のPython問題マスターと指定採点表を読み、既存パーサーで全セット・全版を検証して、gzip＋Base64でScript Propertiesへ保存する。Googleで本人確認した教員2名と、指定デモ用アカウント1名にだけ、問題一覧・問題文・雛形・準備コードを返す。

- 少数の固定サンプルへ縮めず、正本にある全セット・全版を対象とする。
- 問題セットの表示名は配信時に「ページ一覧」の `id`・`title` から作る。`py23a` は `py23` のtitleに `A基本問題`、`b` は `B応用問題`、接尾辞なしは `演習問題` を付ける。先頭の章番号の `. ` は `_` へ揃え、例は `2-3_繰り返し処理（while文）② A基本問題`。対応するtitleの欠落・重複では配信を切り替えない。
- 表示名は配信indexのメタデータに保持し、問題ID・版・雛形・採点基準・下書きのキーを変更しない。ページtitleの変更は次の手動再配信で反映する。利用者の接続時には正本を読まず、再接続で表示名だけ変わっても編集中のコードを保持する。
- 採用前の「編集中」を含む指定アカウント限定のプレビュー。正本の状態、問題の版、課題設定、締切を変更しない。
- 配信・有効化・停止・正本の確認は所有教員だけが行う。追加教員は `teacher`、デモ用アカウントは `demo` roleで配布結果を閲覧する。追加対象への正本GSS共有やGASの編集権限付与は行わない。
- 既存パーサーとの整合性確認のため採点表も読む。基準はGAS内に保持し、ブラウザへは `PythonEditorMaster.publicQuestion` の項目だけを返す。解答・解説・採点基準・原本IDは返さない。
- 生徒別GSSとdist署名bindingを必要とする保存・採点接続は使わない。コードの実行・ブラウザ保存・任意のローカル保存は利用できる。
- 検証GASは既存dist/gradeから分離した新規プロジェクト。同じプロパティキーを使う圧縮処理を既存GASへ配置しない。

## 承認した配置・権限の範囲

| 対象 | 設定 |
|---|---|
| 新規GAS | 指定した学校教員が所有する「PythonEditor 問題配布検証」1件 |
| 実行主体／公開範囲 | 利用者本人として実行 `USER_ACCESSING`／学校ドメイン `DOMAIN` |
| 実際の利用対象 | サーバーのallowlistに明示する教員2名と指定デモ用アカウント1名。管理操作は所有教員のみ |
| OAuth | `spreadsheets`、`userinfo.email` の2スコープ |
| GSS | 所有教員が既存のPython問題マスター・指定採点表を読取。追加教員とデモ用アカウントは圧縮済みデータの問題部分だけ取得。作成・書込・共有変更なし |
| フロント | 新規GASの固定 `/exec` URLを専用設定へ反映。通常の保存・採点設定は無効を維持 |

`spreadsheets` は本人がアクセスできるスプレッドシートの読み書きを許可する広いスコープ。検証コードのSpreadsheet操作は設定した正本の読取だけで、保存先をブラウザから指定させない。Drive・トリガー管理スコープは追加しない。

Googleの[Webアプリ実行主体](https://developers.google.com/apps-script/guides/web#permissions)と[SpreadsheetApp.openByIdのスコープ](https://developers.google.com/apps-script/reference/spreadsheet/spreadsheet-app#openbyidid)を確認した。初回承認画面・学校管理者の制限は実機で確認する。設定した対象アカウントの本人確認と、新規GASの所有教員を確認して配置する。追加教員とデモ用アカウントにも同じWebアプリのOAuth承認が必要だが、コード内で正本GSSを読む操作は所有教員に限定する。

今回の機能はGASの自動作成するデフォルトCloudプロジェクトで開始できる構成で、標準Cloudプロジェクトの手動作成や既存Cloudとの紐付け変更は必須にしない。Cloud Consoleの作成数上限の調査は別に行い、既存プロジェクトを削除しない。[Cloudプロジェクトの仕様](https://developers.google.com/apps-script/guides/cloud-platform-projects)

今年度のColab・HTMLエディタ、既存dist/gradeの公開デプロイ、生徒用GSS、既存共有、正本の採用状態は変更しない。

## 私有の配備候補

実メールや設定値は公開リポジトリへ保存しない。私有の設定JSONに `editorOrigin`、`sourceFileListId`、`teacherAccount`、`additionalTeacherAccount`、`demoAccount`、`gradingSheet` を指定する。`teacherAccount` は所有教員、`additionalTeacherAccount` と `demoAccount` はそれぞれ指定した1名のみとし、省略できる。所有教員の順番は変更しない。現行のColab移行版の `gradingSheet` は `採点設定py_20261014` とする。旧 `採点設定py` は今年度のColab用として保持する。

```sh
node scripts/prepare-pythoneditor-preview-gas.mjs \
  --settings /private/tmp/<検証準備>/settings.json \
  --out /private/tmp/<検証準備>/gas
```

これはネットワークへ接続せず、新しい私有領域へ候補を作るだけ。既存フォルダ・GAS・OAuth・共有設定に作用しない。実project IDや既存 `.clasp.json` は流用しない。全JSをGASの同一globalとして構文確認し、二重iframeのブリッジも `session` だけに絞る。候補の `README.md` に設定・管理操作・停止手順を、`DEPLOYMENT_REVIEW.json` にファイルhash・必要スコープ・アカウント数・無効状態・復元方法を残す。

## 承認後の手順

1. 指定した学校教員・デモ用アカウントと、新規GASの所有教員を確認する。管理操作は所有教員のログインで行う。
2. 新規プロジェクトだけへ候補を配置し、2スコープ・利用者実行・学校限定を確認する。
3. `run_setupTeacherPreview` で無効の専用設定を作る。別設定がある場合は置換しない。
4. `run_inspectTeacherCatalog` で全セット・版・項目数とdigestを確認する。正本の更新・採用は行わない。
5. `run_publishTeacherCatalog` で圧縮・復元・hash照合後に配信世代を切り替える。
6. 新規Webアプリの配備・読戻しを確認し、`run_enableTeacherPreview` で指定世代の入口を有効にする。その固定URLをフロント専用設定へ反映し、公開HTTPを確認する。
7. 教員と指定デモ用アカウントの学校実機で下記を確認する。初回承認は必要に応じてログイン確認リンクの別タブから行う。

指定アカウント限定の問題配信には取得期限を設けない。接続のたびに学校アカウント・許可一覧・配布の有効状態を検証する。取得期限の延長を目的とする再配信は不要。問題や表示名を更新する場合は所有教員が手動で再配信し、自動同期トリガーは作らない。期限なしはこの配布専用GASの圧縮パッケージだけに明示し、正式採点用の既定の期限検証は維持する。同じID・版の内容が変わった場合は差替えを拒否するため、検証中の正本修正が必要なら扱いを別途決める。

## 学校実機のチェック

- 指定教員と指定デモ用アカウントのChrome・Safariで初回承認、問題一覧・本文・雛形・準備コード・大問/小問を確認する。接続開始から取得完了までの総時間はお知らせに表示する。
- 問題切替と再接続で書きかけを保持し、遅れた応答が編集内容や実行を上書き・停止しないことを確認する。
- 通信断、認証切れ、教員による配布停止から再接続し、コードが保護されることを確認する。
- 指定デモ用アカウントが `demo` と表示され、教員の正本確認・配信・有効化・停止操作を実行できないことを確認する。
- 対象外のアカウントへ問題を返さず、教員・デモともクラウド保存・正式提出・採点が有効にならないことを確認する。
- 無限ループ停止、input、エラー、グラフを学校Macで確認する。今回の変更は実行エンジンを変えない。

教員2名と指定デモ用アカウント1名の配布検証は、一般生徒の権限設定、実40名同時利用、GSS自動保存、貸出機復元、正式提出の締切・再送・旧版採点を検証したことにはならない。

## 停止・復元

検証GASで `run_stopTeacherPreview` を実行し、フロント専用設定を `enabled:false` へ戻す。圧縮データや正本は削除しない。既存授業用デプロイ・共有を変えないため、旧Colab/HTMLの巻戻しは不要。フロント変更は今回のコミット単位で戻せる。

## 指定アカウント限定配布の取得期限（2026-10-16）

作成者の指定により2時間の取得期限を廃止する。配信メタデータの `expiresAt:null` は、この限定配布専用GASだけが明示して使用する。既存の採点用パッケージは期限必須のまま。接続ごとの本人確認・許可一覧・停止状態・版固定・hash照合を継続する。問題や表示名を変えるときだけ再配信が必要で、Googleの認証が切れた場合は通常どおり再認証する。
