# 教員・指定デモ用アカウントでの問題配布・実機検証

2026-10-16。対象は学校の教員アカウント1名と、明示指定した高1デモ用アカウント1名による問題一覧・問題文・雛形の取得。この範囲の新規GAS・OAuth・専用接続は承認済み。配置・接続の実施状況と学校実機での確認結果は別に記録し、コードや合成テストの完了だけで実機検証済みとは扱わない。

## 配布の流れ

教員が検証用GASで手動配信する。「配付ファイル一覧」のPython問題マスターと指定採点表を読み、既存パーサーで全セット・全版を検証して、gzip＋Base64でScript Propertiesへ保存する。Googleで本人確認した教員1名と、指定デモ用アカウント1名にだけ、問題一覧・問題文・雛形・準備コードを返す。

- 少数の固定サンプルへ縮めず、正本にある全セット・全版を対象とする。
- 採用前の「編集中」を含む指定アカウント限定のプレビュー。正本の状態、問題の版、課題設定、締切を変更しない。
- 配信・有効化・停止・正本の確認は教員だけが行う。デモ用アカウントは別の `demo` roleで配布結果を閲覧し、教員や管理者として扱わない。正本GSSをデモ用アカウントへ共有する必要はない。
- 既存パーサーとの整合性確認のため採点表も読む。基準はGAS内に保持し、ブラウザへは `PythonEditorMaster.publicQuestion` の項目だけを返す。解答・解説・採点基準・原本IDは返さない。
- 生徒別GSSとdist署名bindingを必要とする保存・採点接続は使わない。コードの実行・ブラウザ保存・任意のローカル保存は利用できる。
- 検証GASは既存dist/gradeから分離した新規プロジェクト。同じプロパティキーを使う圧縮処理を既存GASへ配置しない。

`spreadsheets` は本人がアクセスできるスプレッドシートの読み書きを許可する広いスコープ。検証コードのSpreadsheet操作は設定した正本の読取だけで、保存先をブラウザから指定させない。Drive・トリガー管理スコープは追加しない。

今回の機能はGASの自動作成するデフォルトCloudプロジェクトで開始できる構成で、標準Cloudプロジェクトの手動作成や既存Cloudとの紐付け変更は必須にしない。Cloud Consoleの作成数上限の調査は別に行い、既存プロジェクトを削除しない。[Cloudプロジェクトの仕様](https://developers.google.com/apps-script/guides/cloud-platform-projects)

今年度のColab・HTMLエディタ、既存dist/gradeの公開デプロイ、生徒用GSS、既存共有、正本の採用状態は変更しない。

## 私有の配備候補

実メールや設定値は公開リポジトリへ保存しない。私有の設定JSONに `editorOrigin`、`sourceFileListId`、`teacherAccount`、`demoAccount`、`gradingSheet` を指定する。`demoAccount` は指定した1名のみとし、省略時は教員だけの検証となる。 現行のColab移行版の `gradingSheet` は `採点設定py_20261014` とする。旧 `採点設定py` は今年度のColab用として保持する。

```sh
node scripts/prepare-pythoneditor-preview-gas.mjs \
  --settings /private/tmp/<検証準備>/settings.json \
  --out /private/tmp/<検証準備>/gas
```

これはネットワークへ接続せず、新しい私有領域へ候補を作るだけ。既存フォルダ・GAS・OAuth・共有設定に作用しない。実project IDや既存 `.clasp.json` は流用しない。全JSをGASの同一globalとして構文確認し、二重iframeのブリッジも `session` だけに絞る。候補の `README.md` に設定・管理操作・停止手順を、`DEPLOYMENT_REVIEW.json` にファイルhash・必要スコープ・アカウント数・無効状態・復元方法を残す。

## 公開候補に含める依存

2026-10-16の公開候補は `origin/main` の `8f5bdf7` を基準に、`124b2db`・`da6d4c6` の配布プレビューだけを移植した。追加する共有モジュールは圧縮・hash照合・版固定を担う `30_grading_packages.js` のみ。学生採点・同期・collector・トリガー用モジュールは含めない。通常のクラウド設定は無効。問題配布専用設定には確認済みの新規GASの固定URLを設定し、有効にしている。

配備候補で参照する既存 `05_tools_store_contract.js` と `46_python_editor_master.js` はmainのままとする。先行枝の05との差分は今回使わない学生採点表の定数のみ。46との差分は今回呼ばない `read()` とその内部読取関数のみで、プレビューは専用の読取処理を使う。問題を検証する `build()` と公開項目を限定する `publicQuestion()` は同一。採点表N列の配付URL数式だけを許可する処理はプレビュー専用読取側にある。

同一セット・版の内容変更と、セットをまたぐ同一問題ID・版の重複は、実配置候補と同じ30の検証で拒否する。拒否時は直前の配信世代を保持する。生成物のJSは7件だけであることもテストする。

## 承認後の手順

1. 指定した学校教員・デモ用アカウントと、新規GASの所有教員を確認する。管理操作は教員のログインで行う。
2. 新規プロジェクトだけへ候補を配置し、2スコープ・利用者実行・学校限定を確認する。
3. `run_setupTeacherPreview` で無効の専用設定を作る。別設定がある場合は置換しない。
4. `run_inspectTeacherCatalog` で全セット・版・項目数とdigestを確認する。正本の更新・採用は行わない。
5. `run_publishTeacherCatalog` で圧縮・復元・hash照合後に配信世代を切り替える。
6. 新規Webアプリの配備・読戻しを確認し、`run_enableTeacherPreview` で指定世代の入口を有効にする。その固定URLをフロント専用設定へ反映し、公開HTTPを確認する。
7. 教員と指定デモ用アカウントの学校実機で下記を確認する。初回承認は必要に応じてログイン確認リンクの別タブから行う。

配信データは2時間で期限切れになり、その後の取得を拒否する。延長は教員が手動で再配信する。自動同期トリガーは作らない。同じID・版の内容が変わった場合は差替えを拒否するため、検証中の正本修正が必要なら扱いを別途決める。

- 指定デモ用アカウントが `demo` と表示され、教員の正本確認・配信・有効化・停止操作を実行できないことを確認する。
- 対象外のアカウントへ問題を返さず、教員・デモともクラウド保存・正式提出・採点が有効にならないことを確認する。
- 無限ループ停止、input、エラー、グラフを学校Macで確認する。今回の変更は実行エンジンを変えない。

## 停止・復元
