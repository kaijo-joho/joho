# GSS下書き・正式提出の実装

2026-10-14。ソースとローカル検証は実装済み。承認を受けてgradeのHEADへ配置し、提出ログGSSに専用4シートを追加した。接続は無効で、採用・受付設定、生徒の実保存・正式提出は未実施。実GASでの配置確認と残件は[PLACEMENT.md](PLACEMENT.md)を参照。

## 生徒の操作

学校アカウントに接続した後、ファイルメニューの「GSSに下書き保存」「GSSから開く」を使用する。自宅・貸出機・自端末で同じ問題IDと版の続きを選べる。GSS側と異なる場合は、GSSの続きを取り込むか、ローカルの続きを保存するかを明示選択する。GSS履歴は追記式、ローカルは取り込み前に控えを作る。控えが作れなければ取り込まない。

「正式提出」では送信する1問のコード全文を確認する。GSS下書き保存では提出されない。実行・ローカル進捗と、正式得点・提出履歴は別表示。結果行の永続化・読戻しまで終えてから提出済みとする。通信断・応答消失時は結果照会、必要時は同じ不変送信の再試行を行う。未受付なら、再送がサーバーに到達した時刻で新たに受け付ける。

## 正本と保存先

| 用途 | 場所 | 内容 |
| --- | --- | --- |
| 問題の編集正本 | 配付ファイル一覧GSSのPython問題マスター | 従来どおり1枚。問題・雛形・採点基準への参照を編集 |
| 受付設定の正本 | 同GSSの課題設定 | 新版専用の`item=pythoneditor`。旧`item=py`等は保持 |
| 採用版 | 非公開の保存GSSのPython採用版 | 問題・雛形・準備コード・区間・基準・判定エンジン版を固定 |
| 下書き | 同GSSのPython下書き履歴 | 本人・問題・版・更新番号・親番号・コード・入力値。追記式 |
| 提出受付 | 同GSSのPython提出受付 | 本人・送信番号・サーバー到着時刻・受付時の締切・版・全文・実行テキスト |
| 採点結果/履歴 | 同GSSのPython提出結果 | 各受付の得点・判定・採点時刻・成績対象判定。追記式 |

承認された保存先は既存の「課題ファイル提出_受け取りログ」GSS。既存16シートの後へ専用4シートを追加し、各A1:AH1の見出しだけを作成した。既存16シートのメタデータ・見出しは不変で、提出本文・成績は読んでいない。個別共有3編集者と1所有者で、ドメイン/一般公開共有はない。別GSSを選んでもコード変更は不要。初期化時には共有先をCommonの教員リスト・実行者と照合するが、現在は1件が一致せずstorage_not_readyで停止する。権限や照合条件は変更していない。

各技術シートは34列。共通索引・時刻・SHA-256・メタJSON10列と本文24列を持つ。本文は`j:`接頭辞のJSONテキストを最大40,000文字ずつ分割し、数式として評価させない。UTF-16のサロゲート対を分断しない。コード・入力は各200,000文字、実行テキストは各100,000文字、保存本文は最大960,000文字。超過を切り捨てて保存せず、エラーとして保持する。列11以降は初期化時に非表示とする。GSSの直接編集・履歴行削除は通常運用で行わない。

## 認証と配信

既存gradeの学校アカウント/名簿/Common教員判定を使用する。生徒本人と学年は毎回サーバーで取得し、clientのメール・学年・点数を権限や得点として信用しない。教員は閲覧・採用操作ができるが、生徒の成績として提出しない。再認証でアカウントが変われば、以前のアカウントに結び付いた送信要求を拒否する。送信控えも本人別に分ける。

独立エディタとGASのHtmlServiceを、nonce・送信元origin・応答元Windowを結合した`postMessage`で接続する。実際のRPCは`google.script.run`を使用する。URLパラメーターからGAS接続先を受け取らない。課題の版・利用対象・受付条件はサーバー側で照合し、開始前の問題は返さない。初期設定なし/無効・認証切れ・利用対象外・停止時は閉じて拒否する。認証拒否をデモや別の課題取得経路で迂回しない。

フロントの`cloud-config.mjs`は現在`enabled:false`。既存のlocalhost問題マスター表示は教員のプレビューであり、本番認証とは別。接続時に同じID・版の問題内容が違えば差替えを拒否する。応答が遅れても、編集中のコードや実行を置換・停止しない。保存・提出のコールバックは開始時の問題・版・本人へ固定する。

参考: [HtmlServiceとiframe](https://developers.google.com/apps-script/guides/html/restrictions)、[RPCと非同期応答](https://developers.google.com/apps-script/guides/html/communication)、[ALLOWALL](https://developers.google.com/apps-script/reference/html/html-output#setXFrameOptionsMode(XFrameOptionsMode))。

## 受付設定

スクリプトプロパティ`PYTHON_EDITOR_CONFIG`はschema=1、enabled、editorOrigin、storageSpreadsheetId、assignmentIdsのみに責務を限定する。締切や学年を別に複製しない。`assignmentIds`で指定した課題設定行について、次を読む。

| 欄 | 新版での意味 |
| --- | --- |
| id | 受付設定の識別子。年から始まる既存の形式も使用可 |
| item | `pythoneditor`のみ。旧`py`行を選んだ場合は拒否 |
| targetId | 問題セットID |
| subTargetId | 固定された問題版 |
| year / grade | 年度・対象学年 |
| status | `active`で正式提出、`practice`で下書き/閲覧、`closed`で停止 |
| gradingMode | 正式採点は`auto`。`closed`は停止 |
| startAt | 問題を表示し受付を開始する時刻 |
| standardDueAt | 成績採用の締切 |
| finalDueAt | 締切後も学習用の提出を受け付ける最終時刻 |

日時はGSSの日時値、または厳密なUTC ISO形式。未設定・重複・不正日時は拒否する。初版は`submitOnly`に対応しない。年度・学年・期限・採用版はこの作業で推測して設定していない。

## 採用版と判定

教員が`previewPythonEditorVersion({setId,version,gradingSheet})`で件数・区間・SHA-256を確認し、そのdigestで`adoptPythonEditorVersion`を呼ぶ。全選択行が採用済み/旧版になっている場合のみ、保存GSSへ固定版を追記する。編集中の状態を自動で採用済みにしない。同じ版を異なる内容で採用し直すことは拒否し、新しいversionを要求する。部分的な書込失敗は、同じdigestで再実行して同じ内容の不足分だけ回復する。

現在の125件は全て編集中のため、構造のプレビューは可能だが採用・正式提出は無効。22セット125件すべてを変換し、119件を採点基準へ結合できる。残る6件は既存の発展/観察用で正式採点なし。旧版答案を別版へ自動変換せず、その版の固定された問題・雛形・基準で判定する。

固定エンジン`legacy-python-text-20261014-v1`は、gradeのリモートHEADから確認した02/10/12/15の純粋な判定関数を専用namespaceへ取り込む。既存デプロイ版132でも4原本が同一であることを確認した。4原本のSHA-256をソース冒頭に記録。旧global関数を置換せず、旧`採点設定py`は読取/更新しない。採用操作で指定した基準だけを固定する。

サーバーが固定版のscoringRangesを使って採点区間を取り出す。startMarkerからendMarkerまで、endMarker=nullなら末尾まで。区間のマーカー削除・重複・順序不正は0点と案内を返し、全文採点へ迂回しない。py33の複数区間は現行の重みで親問へ集約する。条件名・keyword・解答・教員メモは採点結果にも返さない。未実行・停止・出力上限時は出力を採点に使わず、randomの出力除外は現行規則を引き継ぐ。

送信するrunは、実行コードhash、outcome、truncated、表示テキスト、stdout、入力表示、stderr、エラー全文。表示テキストは現行Colabのstream/text/plainに対応する。入力・警告などは分離して保持する。コードhashは古い実行結果の誤送信検出用で、ブラウザ出力の改変防止証明にはならない。サーバーが送信テキストを基準で判定し、ローカルの合否・点数は送信契約に含めない。初版はPythonをサーバーで再実行しない。

## 締切・再送・完了

GASのRPC入口で、認証・正本読取・ScriptLock待ち・採点より先に受付時刻を確保する。その時刻を、全文と採用版hash・受付時の締切とともに受付行へ固定する。締切ちょうどは対象、1ミリ秒後は対象外。採点の遅れで時刻を変えない。同じ本人・requestIdの再送は、全文・入力・実行記録が同一の場合だけ、元の受付行を使用する。内容が変われば拒否する。

受付行へのロック混雑・書込失敗の応答には、本人・送信番号・本文hash・採用版hash・期限を結合した署名付きの到着証明を返す。控えに保持して再送し、元のサーバー到着時刻を採用する。HMAC鍵は初期化時にScriptPropertiesへ生成し、ブラウザや公開ファイルへ返さない。受付行も到着証明の応答も失われた場合は、元の受付を証明できない。その場合は保持した要求を再送し、再送の到着時刻になる。ブラウザ時計や押下時刻で補正しない。

結果行1件が採点結果と再提出履歴の正本。結果と受付のhashを検査し、結果行の読戻しまで完了して初めてsubmittedを返す。途中失敗はpendingで、同じIDから再処理可能。最新の提出より古いpendingも一覧から回復できる。成績の最高点は本人・年度・問題セット・問題IDで、固定された締切内の全結果から求める。別版も同じ問題の再提出として集約し、それぞれはその旧基準で採点する。締切後の結果は履歴に残すが最高点へ含めない。UIは最近20件を表示するが、保存履歴は削除しない。

## 配置と復元

GAS追加ソースは`scripts/pythoneditor-gas/`。8ファイル、既存doGetへ新版kindの1行、filePushOrderへの追加、作業記録のみ。既存py/ss/htmlの本体、Common、appsscript.json、.clasp.jsonのscriptId、既存デプロイIDは保持する。

`node scripts/prepare-pythoneditor-gas.mjs --baseline <確認済みリモート原本> --out /private/tmp/<新しいrelease>`で配置用コピーと変更一覧/原本hashを作る。実フォルダ・設定・本番には作用しない。2026-10-14は66ファイルのリモート原本から用意し、旧ルートの1行以外のコードが不変なこと、追加後もJSがまとめて構文解析可能なことを検証した。配置直前に原本を再取得し、hashが変わっていれば再作成する。Apps Script APIのソース配列から実ファイル名と順序を確認し、baselineのfilePushOrderを全件の順序に合わせてから準備する。ローカルの未コミットGASを一括pushしない。

無効でのHEAD配置と専用4シート追加は確認済み。共有先1件の照合が未解決のため、初期化完了・署名鍵生成は未実施。接続有効化の前に共有先の扱い、採用する問題版・対象行・日時を確認する。既存の権限を勝手に変更せず、初期化と学校アカウントでの限定テストを完了してから受付を有効にする。教材サイトの掲載・既存リンク切替はこの作業から独立。

復元はプロパティenabled=falseで新版の書込を止め、保持したGAS原本/既存デプロイ版へ戻す。旧Colab・旧py設定・配付リンク・旧ログの変更はない。新版に保存した行は削除せず、提出履歴として保護する。権限を変更したり、別経路で認証を迂回したりしない。
