# Pythonエディタの導入予定と保存提出の取り決め

2026-10-17の合意を記録する。授業での利用開始は2027年4月、本番環境への切り替えは2027年1〜3月を予定する。以下の本運用設計と、現在の3名限定試用で実装・検証できている範囲を区別する。既存文書に残る旧gradeでの再採点や夜間だけの回収案については、本書と[取組評価の新方針](CONTRACT.md#取組評価への方針変更2026-10-17)を優先する。

| 時期 | 取り決め |

予定時期の合意は、本番GAS反映、OAuth・学校設定・権限変更、公開範囲や既存教材リンクの切り替えを自動実行する許可ではない。対象と復旧手順を具体化して、必要な確認を受ける。リマインダー自体では切り替えを行わない。

## 本運用での役割分担

| 担当 | 保存先と処理 |
|---|---|
| 問題配信用GAS | 教員管理のPython問題マスターを正本とし、採用版の問題・雛形・判定条件を配信する。圧縮した問題・採点基準はこのプロジェクトのScriptPropertiesで管理する |
| dist | 個別フォルダの台帳と同様に本人用の保存GSSIDを管理する。教員権限で作成・取得・共有・保護・構成変更を担当する |
| 保存・提出・転記用GASの生徒向け窓口 | 生徒本人の権限で個人GSSへ下書き・履歴・試行・提出を保存する。提出を受け付け、署名付きの転記待ち要約を同じGASのScriptPropertiesへ置く |
| 同じGASの教員向け処理 | 教員権限で転記待ち要約を取り出し、教員専用GSSへまとめて転記する |

問題配信用と保存・提出・転記用は別のGASプロジェクトとする。ScriptPropertiesの容量も別枠で、問題本文・模範解答が提出待ち要約の容量を圧迫する構成にはしない。生徒権限の受付と教員権限の転記は、保存・提出・転記用の同じプロジェクトに置いて待機記録を共有する。別プロジェクトのプロパティを直接読む設計にはしない。

個人GSSは教員所有、本人に編集権限を付ける。編集者の再共有は無効とし、固定設定・見出しを保護する。データシートの非表示と保護は誤操作防止であり、機密化や採点結果の真正性の根拠にはしない。保存本文はテキストで扱い、Drive上の個別ファイル保存を基本経路にしない。

## 下書き保存と復元

- ブラウザ内には即時自動保存する。生徒にはJSONファイルへのローカル保存を基本操作として案内する。
- クラウド下書き保存は問題・セットの切り替え、手動保存、提出、保存して終了を中心に行う。保険の定期送信は変更がある場合だけ10分間隔とし、変更がなければ送らない。
- 下書き保存のたびに転記待ち要約を作らない。ScriptPropertiesへ待機記録を置くのは正式提出の受付時とする。
- 貸出機では個人GSSから復元し、戻った端末でも続きを取り込めるようにする。取り込み前のローカル内容を控えに残し、競合時は両方を保護する。
- 下書き保存と正式提出は独立させる。保存済みを提出済みとして扱わない。詳しい保存契約は[TOOLS-CLOUD.md](TOOLS-CLOUD.md)。

## 採点と提出の受付

取組状況の測定を目的として、ブラウザ内のローカル判定を採用する。コード全文、該当する実行・試行・回答、ローカル判定結果、問題と判定条件の版をテキスト送信する。サーバーでPythonを再実行する方式は採用しない。出力条件を持つ問題では、その判定に使った出力も固定した提出本文に含める。

受付GASは本人・対象問題・版・本文hash・判定結果の形式と集計の対応を検査し、サーバー受付時刻と署名を付ける。署名は受付後の改変検出に使い、ブラウザで実行した事実や厳密な正答を保証するものにはしない。模範解答・非公開正答・秘密鍵はブラウザへ出さない。

締切はブラウザの押下時刻ではなくサーバー到着時刻で判定し、ロック待ち・保存・転記より前に確保する。再提出を認めて各回の履歴を残し、小問ごとに締切内の最高点を成績へ採用する。締切後の結果は履歴に残すが、成績へ反映しない。旧版は旧問題・雛形・判定条件へ結び付ける。22時の締切が多いという運用例を全課題共通の締切として設定しない。

## 転記待ち要約の方式

以下は合意した本運用の設計方針であり、現在の試用版には未実装。

1. 個人GSSへ提出本文と署名付き受付を保存する。
2. ScriptPropertiesに、本人識別子・固有の提出ID・問題IDと版・判定条件の版またはhash・得点と分母・★・サーバー受付時刻・本文hash・要約自体の署名を含む小さな記録を保存する。コード全文・出力・試行明細は個人GSSに残す。
3. 個人GSSと転記待ち記録の両方の保存を確認して提出完了とする。途中失敗や応答消失は、同じ提出IDの照会・再送で不足分を補い、受付時刻を保持する。
4. 教員側はその回に読み取った未転記要約を教員GSSへまとめて書く。点数・提出状況の集約だけなら、各個人GSSを毎回開かない。コード確認や履歴の照合は別に個人GSSを読む。
5. 転記を読戻しで確認できた提出のキーだけを削除する。失敗・成否不明の記録は残し、教員GSSでは本人と提出IDを照合して重複を防ぐ。

プロパティは生徒ごとの固定50枠を事前確保せず、本人識別子と提出IDから一意なキーを動的に作る。同じIDへ異なる本文を上書きせず、再提出は新しいIDで保持する。全員分を一つのJSON配列へ読み出し・追記・書き戻しする方式や、全プロパティを空にする処理は使わない。転記中に届いた別IDの提出を、古い一覧で削除しない。

保存・提出は本人単位で直列化し、他の生徒とは並行処理する。転記処理同士の重複実行は防ぐが、教員GSSへの書込み中に全生徒の受付を共通ロックで待たせない。

プロパティの「50件」は管理画面から手動追加する際の制限であり、プログラムからは超えて作成できる。容量は1値9KB・1ストア全体500KB。容量は全生徒で共有し、転記前に蓄積する最大件数と実際のバイト数を測る。満杯や転記停止時に古い記録を捨てる方式は採らず、未完了の表示・再送・個人GSSからの復旧手順を整備する。[Propertiesの公式仕様](https://developers.google.com/apps-script/guides/properties)、[利用上限](https://developers.google.com/apps-script/guides/services/quotas#current_limitations)。

## 転記頻度と利用時間

試用版は `run_collectSchoolTrial` の手動実行だけとし、定期回収トリガーを設置しない。

本運用では昼間も未転記要約をまとめて転記する方式を候補とする。5〜10分ごとは提案段階で、間隔は授業時の件数・容量・処理時間を実測して決める。夜間だけの回収に限定しない。自動保存時刻の分散も負荷対策の候補であり、未実装。明示した提出操作は直ちに送信を始め、再送は同じ提出IDで間隔をあけて行う。

23時〜翌5時は生徒の利用を制限するメンテナンス時間帯とする方針。昼間のまとめ転記とは独立させる。具体的な制限対象、境界時刻の扱い、処理中の保存・提出の扱い、夜間の照合・復旧の要否は実装前に詰める。

## 本番切り替えまでの検証

| 段階 | 確認する内容 |
|---|---|
| 3名限定の試用 | 別の本人・権限での接続、保存・復元・提出・照会・手動回収。所有教員で通過した範囲と、残る2名の実ログインを区別する |
| 同時処理・障害試験 | 同時提出、転記中の新規提出、連続提出、二重転記、個人GSS保存後の要約保存失敗、転記後の削除失敗、通信断・認証切れ・再送、容量不足、転記停止からの復旧 |
| 学校実機と授業負荷 | Jamf管理Mac、Chrome/Safari、40名の別アカウントで保存・提出・転記が重なる状態。貸出機と自宅からの継続、締切前後、旧版、無限ループ停止 |
| 切り替え判定 | 問題・雛形・判定条件の採用版整合、履歴と小問別最高点、署名と重複排除、権限、監視、復旧手順、生徒向け操作案内 |

保存・提出の所要時間、失敗と再送、ロック待ち、未転記件数・最古の待機時間・使用容量、転記所要時間を測る。平均だけでなく、問題切り替え・授業終了時の集中と転記停止時の蓄積を見る。欠落・重複がないことを照合する。本文・署名鍵・個人情報を診断ログへ出さない。

3名の動作確認と合成の40並列試験は、40名の実アカウントによる授業負荷の検証とは区別する。実測前に「40人運用済み」と報告しない。

## 現在の実装との違いと再開時の入口

現行の3名限定試用は、一つの限定GASへ問題取得・保存・提出・回収をまとめている。回収は3名の個人GSSを読み、提出本文を含む記録を教員GSSへ移す実装。上記のプロジェクト分離、ScriptProperties待機記録、要約だけの転記、定期転記、メンテナンス時間帯の利用制限は未実装。通常モードの本番保存・提出接続は無効のまま。

再開時は[学校試用](SCHOOL-TRIAL.md)の実機確認記録と、[契約](CONTRACT.md)、[問題マスター](MASTER-SCHEMA.md)、[保存・復元](TOOLS-CLOUD.md)を確認する。設定変更前に実際の対象アカウント・所有者・権限・配信版を読み戻す。切り戻しは新版の接続・処理を止めて旧経路を維持する方法を具体化し、個人GSS・教員GSS・履歴・受付時刻・署名鍵・再送控えを削除しない。
