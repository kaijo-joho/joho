# 生徒権限GASでの採点（2026-10-15・本番未反映）

今回の実装は新しい保存用GASへ追加する候補コード。本番GAS、ScriptProperties、OAuth、共有、実GSS、トリガーは変更していない。フロントの `enabled` / `studentGrading` もfalse。今年度の旧Colab・旧grade・HTMLエディタ・既存リンクを維持する。

## 構成

```text
教員：Python問題マスター＋新版採点表 → 採用版を明示確定 → 教員限定GSS「Python採用版」
                                                       ↓ 教員の定期同期
同じ新規保存GASのScriptProperties：gzip＋Base64、固定版・課題設定・本人権限・保存先対応
                                                       ↓ 学校認証済み本人として実行
生徒エディタ → 保存用GAS → 本人GSS：署名付き受付 → サーバー採点 → 署名付き採点結果
                                                       ↓ 教員の定期回収
教員限定GSS：受付・結果・履歴を読戻し確認 → 本人GSSへ署名付き完了記録
                                                       ↓ 本人として結果照会
エディタ：正式提出済み・正式得点・履歴・最高点・★
```

生徒ごとに同じコードを本人として実行する。40名の提出を教員1人の採点実行へ集中させず、本人GSSへ分散する。教員側の中央保存だけを少量ずつ回収する。ブラウザ内の採点結果や点数は信用せず、従来のテキスト判定エンジンをGAS内で使う。Pythonのサーバー再実行はしない。

## 圧縮された基準と採用

- 問題編集の正本は引き続き「Python問題マスター」1枚。採点設定の旧 `採点設定py` は変更せず、新版用の表を指定する。
- 教員が版・採用状態・対象課題を確定する。編集中の問題を定期処理が勝手に採用しない。中央の不変な採用版を同期元とし、同じ問題ID＋版の本文・雛形・基準の差し替えを拒否する。
- 旧版も圧縮データへ残す。古い解答は当時の問題・区間・基準・受付時の期限で処理する。旧版を消して容量を空ける自動処理は行わない。
- 採用版、課題設定、名簿由来の本人権限、保存先対応をgzip＋Base64でScriptPropertiesへ保存する。ブラウザには許可された問題・雛形・自分の結果だけを返す。採点基準、模範解答、名簿、鍵を返さない。
- 分割値は7,600文字のBase64（各8,000 byte未満）。既存設定、現行・退避・準備中データを含め、合計450,000 byteを安全側の上限とする。Googleの上限へ到達する前に停止する。
- 準備世代を書込み・復元・hash検証してからactive pointerを切り替える。ソース変更・権限エラー・同じ版の競合・容量不足では直前のactiveを保持する。同期世代の整理と、旧採用版の保持を区別する。
- activeと直前の同期世代を残し、それ以前の同期世代だけを整理する。名簿は全件検証し、配信データの本人権限は保存先登録済み本人と許可教員に絞る。保存先未登録の全校生徒を毎回格納しない。
- 同期の候補は60分ごと、権限情報の有効期間は120分。同期失敗が続き期限切れになったら新規配信・採点を停止し、権限拒否を別経路で迂回しない。緊急の停止・名簿変更は手動同期または採点フラグ無効化で反映する。この間隔は学校実測後に調整する。

圧縮は暗号化ではない。教員所有のGASプロジェクトとScriptPropertiesを生徒へ編集共有しないことが前提。ScriptPropertiesは別プロジェクトと自動共有されないため、教員の同期と生徒の採点は同じ新規プロジェクト内へ配置する。

## 本人GSSと正式提出

既存の `Python` / `Python履歴`（14列）は下書き用のまま。追加するのは以下の3シートで、各34列・2,049行（見出し＋2,048件）。教員のdist準備操作だけが作成・増設する。見出しを教員限定で保護し、シートを非表示にする。本文は本人が編集可能なので、保護や非表示を正式得点の保証には使わない。

| シート | 記録 | エディタでの扱い |
|---|---|---|
| Python提出受付 | 送信番号・本人・問題/版・コード全文・入力・実行テキスト・元の受付時刻・期限 | 受付済み、提出処理中 |
| Python提出結果 | GASが計算した結果・チェック・診断 | 採点結果（教員側保存待ち） |
| Python提出完了 | 教員が中央保存と履歴の読戻し後に発行する完了記録 | 正式提出済み、正式評価・★ |

受付・採点結果・完了記録には異なるHMAC用途を用い、本人・保存先GSSID・鍵の版を署名へ結合する。本人GSSで点数や期限を書き換えたり、結果行を完了表へコピーしたりしても受理しない。削除や破損を空の新規データと判断して勝手に復元・上書きしない。

提出時刻は `toolsStoreRpc` の入口で、認証・UserLock待ち・採点より前に取得する。ブラウザ押下時刻は使わない。締切ちょうどは対象、1ms後は対象外。採点・回収が遅れても時刻は変更しない。受付書込失敗時に返せる署名付き到着証明は送信控えへ保存する。受付も証明の応答も失われた場合は元の到着を証明できず、再送時の到着時刻になる。

1問のコード全文を保存し、固定版の採点区間だけを判定する。送信項目はコード・入力に加え、実行時コードhash、終了区分、出力上限到達、表示テキスト、stdout、入力表示、stderr、例外全文。ローカルの合否や点数は受け付けない。出力テキスト自体の改変を検出する方式ではなく、現行テキスト判定を引き継ぐ初版の範囲である。

本人＋送信番号を不変にし、再送の本文変更を拒否する。途中失敗と応答消失は同じ要求を照会・再処理する。教員回収は中央の受付と結果・全履歴を保存・読戻ししてから本人へ完了記録を発行する。途中停止しても次回同じ行から再開でき、中央記録を重複させない。

旧版の採用版だけでなく、課題設定と許可対象assignmentIdも履歴確認に必要な間は保持する。最終受付時刻を過ぎた新規提出は拒否し、受理済みの処理再開と元の署名付き到着証明を伴う同一要求の再送を分ける。課題設定を削除・無効化して配信権限も取り下げる場合は、先に未完了提出を回収・確認する。

中央保存前の採点結果は表示できるが、正式な★、最高点、提出済み、成績へ加えない。中央完了記録から、1問ごとの締切内最高点とその提出の★を求める。締切後の結果は履歴に残す。画面の履歴表示を絞っても保存履歴は削除しない。

## 教員による自動同期・回収

同じGASの教員作成トリガーは作成者の権限で動く。生徒のRPCと教員処理の入口を分離し、教員用関数は末尾 `_` にして `google.script.run` から呼ばせない。手動はactive/effective教員の一致、トリガーは作成者・登録UID・自分の所有トリガー・handlerを照合する。

同期は「課題設定」のallowlist対象 `item=pythoneditor` と、中央の採用版だけを読む。`PYTHON_EDITOR_CONFIG.enabled=false` のままでも同期の準備は可能。旧gradeの受付を有効にする必要はない。「生徒名簿」の `userId` / `年` と「個別フォルダ」の `userId` / `tools保存用GSSID` を教員権限で取り込み、生徒の提出中には教員GSSを読まない。

教員用の候補関数（今回未実行）:

| 関数 | 用途 |
|---|---|
| `previewToolsGradingAdoption_(spec)` | setId/version/gradingSheetを指定し、digest・採用可否・件数だけを確認 |
| `adoptToolsGradingVersion_(input)` | spec・expectedDigest・`confirmation:'ADOPT_TOOLS_GRADING_VERSION_V1'`を照合して中央へ固定。`syncAfter:true`なら続けて反映 |
| `previewToolsGradingSync_()` | 同期対象・権限・保存先の件数と版のhashを読取確認 |
| `syncToolsGradingPackages_()` | 教員として固定採用版を圧縮反映 |
| `runToolsGradingCollectionV1_()` | 教員として署名済み採点結果を中央へ回収 |
| `inspectToolsGradingCollectionV1_()` | 教員だけが直近の回収状態・件数・エラー種別を確認 |
| `installToolsGradingSyncTrigger_({confirmation:'INSTALL_TOOLS_GRADING_SYNC_V1'})` | 承認後にのみ、同期の教員トリガーを登録 |
| `installToolsGradingCollectionTriggerV1_({minutes:1,confirmation:'INSTALL_TOOLS_GRADING_COLLECTION_TRIGGER_V1'})` | 承認後にのみ、回収の教員トリガーを登録 |

固定保存とその後の同期は別工程。`syncAfter`で反映だけ失敗した場合も、採用済みデータを取り消したことにはせず `adopted` と `not_published` を分けて返す。採点表N列の配付URL数式は判定対象外として読み、問題・基準・見出し内の数式は拒否する。旧GSSの数式を書き換える必要はない。

結果回収の初期候補は1分間隔、1回5名・各20件、最大約4分の処理予算。cursorを保持して巡回し、1名の不備で全員を止めない。これは1分以内の提出完了を保証する値ではない。40名の回収周期・授業中の結果待ち時間・日次実行時間上限を実測し、間隔・対象人数・運用時間帯を調整する。

`TOOLS_GRADING_COLLECTION_LAST_RUN_V1`へ直近の日時・完了/待機/失敗件数・エラー種別・次cursor・処理時間を8KB未満で保存する。コード、出力、メール、actorKey、秘密鍵は含めない。監視用記録だけが失敗した場合も、中央結果や完了記録を巻き戻さず、教員へ状態保存失敗を返す。

中央GSSは教員所有者・編集者・閲覧者を検証する。Spreadsheetサービスだけではリンク/ドメイン共有を完全には照合できないため、実GSSの共有状態は反映前に別途確認する。以前の中央保存先の共有先確認が未完了なので、そのまま有効化しない。

新しい設定と権限は今回適用していない。対象GAS、所有教員、試験生徒、GSSの対象件数、承認画面と復元方法を確認してから実施する。

基本の `TOOLS_STORE_*` は [保存GASのREADME](../../scripts/tools-store-gas/store/README.md) を参照。新規GASのmanifest候補は `USER_ACCESSING/DOMAIN`、`spreadsheets`、`userinfo.email`、追加の `script.scriptapp`。最後のscopeは教員によるトリガー登録・UID確認に使う。同じプロジェクトのmanifestへ追加するため、生徒の承認画面への影響も学校で確認する。Drive scopeやCommonライブラリは追加しない。

署名鍵とkeyIdを変えると既存行を読めなくなる。初版は同じ鍵を保持し、ローテーションは複数鍵検証・移行の別作業とする。鍵や採点基準の実値をGit、公開ファイル、ブラウザ、ログへ含めない。

反映の候補手順:

1. 現行dist/保存GASの原本・設定を読戻し退避し、配備候補との差分を確認する。
2. 新規GASの所有者・学校限定実行・追加scopeを確認する。既存dist/gradeの実行主体は変えない。
3. 生徒接続と採点は無効のまま、対象を限定してdistの教員prepareで3表を追加する。既存下書き・履歴は変更しない。
4. 正式GSSの共有状態を確認し、教員が採用版と新版課題を確定する。採用同期のpreviewで件数・版・保存先を確認し、手動同期して読戻す。
5. 学校の試験生徒で、本人実行の提出→教員回収→照会・正式★の順に確認する。
6. 承認後に限って同期・回収の教員トリガーを登録する。installerコードを提供するだけで今回実行しない。
7. 実測に基づく40名・認証切れ・通信断・貸出機・期限・旧版の検証後、対象を広げる。教材の既存リンクは切り替えない。

## 配備候補と検証

`scripts/prepare-tools-store-gas.mjs` は最新dist原本から別の `/private/tmp/` へ候補コピーだけを作る。新しい保存GASには採点・同期・回収の4モジュールと既存Python判定の固定コピーを含める。実project IDや `.clasp.json` を新規保存GASへ流用せず、push・デプロイ・設定・権限変更を実行しない。

単体・合成結合テストとブラウザ検証の具体的な結果は [STUDENT-GRADING-VERIFICATION.md](STUDENT-GRADING-VERIFICATION.md) に記録する。学校アカウント、実GASでのgzip/Properties書込、トリガー、40名の本物の同時利用、Jamf管理Mac・実Safariは別途実機検証が必要。

停止・復元は新版の採点・回収・同期・フロント接続を無効化し、教員が作成したトリガーを停止する。保存済みの本人/中央の受付・結果・完了・下書きと署名鍵は削除しない。コードを戻す場合は今回のコミットをrevertでき、旧Colab/grade/HTMLのデプロイを切り替える必要はない。
