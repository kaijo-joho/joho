## 分担と保存先

| 処理 | 担当 |
|---|---|
| 本人・名簿照合、保存先取得/準備、署名接続情報 | 既存distへの専用追加 |
| 共有・保護・構成管理 | 教員として動くdist |
| 日常の自動保存・履歴・復元 | 新しい保存用GAS、生徒本人として実行 |
| 採点と正式提出 | 既存gradeの専用契約。下書きとは独立 |

「配付ファイル一覧」の既存「個別フォルダ」シートに`tools保存用GSSID`を末尾1列追加し、同じ行の`userId`・`個別フォルダID`と対応させる。名簿・台帳・所有者・保存先の不整合では新規GSSへ逃げず停止する。初回準備にはScriptLock、日常保存にはUserLockを使い、全員の本文保存を教員1人のロックへ集中させない。

生徒ごとに教員所有のGSSを1冊。`使い方`を表示、`Python`と`Python履歴`を非表示にする。A1:B6の固定metadataと各データシートA1:N1は教員限定保護。本文は本人が編集できる。D列`フォルダ`が擬似フォルダの1列で、JSONと同じく`j:`付き文字列として安全に記録する。初版はPythonだけを接続し、HTML等のシートは勝手に追加しない。

## 接続

学校アカウントボタン→distの本人/保存先確認→保存用GASで同じ本人を再確認。distが返すのは本人・GSSID・世代・origin・有効期限を固定した専用の署名binding。HTML実習のtokenは流用しない。署名鍵は両GASのScriptPropertiesだけに置き、実値をコードやブラウザへ含めない。

GSSIDと接続情報は本人別のブラウザキャッシュへ保持する。キャッシュは正本や権限証明の代わりにはならず、再開時も保存用GASで本人・所有者・編集権限・構成・世代を検証する。別人への未解決要求の送信は拒否する。

初回はGoogleの承認が必要になる。接続ダイアログに学校ログインと保存用GASの別タブ承認への入口を設ける。iframe内で承認できない場合は別タブで許可し、エディタへ戻って再接続する。bindingや秘密鍵をURLへ入れない。この操作が学校実環境で通るかは承認後の実機確認が必要。

## 自動保存と復元

- ブラウザの本文は即時保存。クラウドは入力停止4秒、前回送信から最低20秒、連続入力中は30秒を目安にまとめ、最大3秒のばらつきを加える。通信は生徒ごとに1件ずつ。応答待ちの編集は次のsnapshotにする。
- 保存対象はコード全文・確認用入力値・問題ID/版・表示名・フォルダ。実行出力画像、問題文、解答、採点基準、正式得点を下書きGSSへ保存しない。
- 書込と読戻し、codeHash/stdinHash、問題・版・revisionが送信した不変snapshotと一致してから保存済みにする。画面の新しい編集には古いackを付けない。
- 同じrequestIdの送信を保持し、応答消失時は`lookupSave`で照会、確認不能なら元のCAS条件・同じ全文/IDで再送する。後続編集に差し替えない。
- 通信断は待機・再試行、認証切れは停止・再接続。ブラウザ保存不能でもRAMの不変要求からクラウド保存を試み、警告を表示する。RAMだけの場合は再起動後の復元を保証しない。
- 初回/再接続時にremoteとlocalが違えば、保存済みrevisionのキャッシュだけで本文を信頼せず、両方を保護する選択画面を出す。貸出機の続きがあるときも同じ。
- 復元前のローカル内容を控えへ退避できなければ取り込みを止める。競合解決でローカルを採用するときはremoteもサーバーのcheckpointに残す。古い版はID/版を保って別に保存し、未読込の問題・版は勝手に変換しない。
- 未ackのクラウド変更がある間は離脱時にブラウザの確認を出す。終了前は下部の「クラウドに保存済み」を確認する。pagehide時の通信完了を保証しない。

最新は256問版、checkpointは2,048件が初版上限。通常5分間隔、端末変更・明示的な競合解決で追加する。全授業205ケースは範囲内だが、新年度/旧版を増やす前に余裕を確認する。満杯では削除せず停止する。容量の増設はdistの構成管理として別途行う。構成・障害時の詳細は[保存用GASの仕様](../../scripts/tools-store-gas/store/README.md)。

## 本番反映前に確認する具体案

1. **新規保存用GAS**：学校管理下で1プロジェクトを作成、`USER_ACCESSING`・`DOMAIN`。OAuthは`spreadsheets`（本人がアクセスできるスプレッドシートの読書き）と`userinfo.email`。保存先1冊に限定されたOAuthスコープではないため、サーバーはdist署名の本人用GSSだけを許可する。Driveスコープ、APIキー、インストール、Terminal操作は生徒へ要求しない。
2. **distの本番変更**：最新ソースを読戻し、既存doGetへ`type=toolsStore`の1ルートと追加3ファイルだけを合成する。既存manifest・HTML/Colab配付本文を保持。既存deploymentの版を控え、追加フラグを無効にしたまま配置・読戻し確認する。
3. **GSS/共有変更**：対象生徒を確定して読取専用preview、台帳を退避後に専用列を1列追加。最初は指定1名、次に10名以下ずつ事前準備。教員所有・本人だけ編集・再共有無効・固定保護を確認する。既存フォルダの共有範囲は変更しない。
4. **設定と初回承認**：両GASの許可origin/学校ドメイン/教員所有者、サーバー署名鍵、新GASの固定URLを設定する。生徒接続・provision・adminを別フラグで制御し、初回Google承認や学校管理者の許可を実機で確認する。実値や鍵はリポジトリへ保存しない。
5. **限定接続**：対象1名の保存・読戻し・別ブラウザ復元・通信断・認証切れを確認し、40名の実測後にPython側だけ有効化する。今年度の旧Colab、HTMLエディタ、教材リンクは切り替えない。

## 検証と復旧

NodeのGAS fakeとブラウザの合成アカウント/GSSを使う。実エディタ、GAS保存本体、署名、二重iframe通信を使用し、Chrome/WebKitの接続・自動保存・遅延ack・通信断・照会・貸出機復元・認証切れ・ブラウザ容量不足を確認する。実GAS40名負荷、初回OAuth、Jamf学校Mac、実Safari、自宅通信は別工程。正式提出の締切・再送・旧版採点と無限ループ停止は既存回帰で確認する。

コードの復旧は今回のコミットだけをrevert。サーバーは両接続フラグを無効化し、distを保持した旧deploymentへ戻す。生徒GSS・保存履歴・ブラウザの送信控えは削除しない。HTML・Colab・gradeの既存経路を巻き戻す必要はない。
